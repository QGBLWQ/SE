## 💡 一句话记忆点

> **FiLM = 让第二路信号只输出"缩放 γ 和平移 β"两组逐通道参数，去调（modulate）主干特征，而不是自己再开一条编码分支。**
> 公式：`FiLM(h) = γ ⊙ h + β`，其中 `(γ, β) = f(c)`。
> 关键词是**调制 (modulate)** 而不是**融合 (fuse)**。

## ❓ 问题

FiLM 是什么方法？为什么 2026 年多模态/多通道轻量化会用到它？

## ✅ 答案

### 1. 名字与来源

**FiLM = Feature-wise Linear Modulation**，逐特征通道的线性调制。原始出处是视觉问答（VQA）领域（Perez et al., AAAI 2018），当时的用法是"用问题的文本嵌入去调制图像的 CNN 特征"。**它不是语音领域发明的，是从视觉迁移过来的。**

### 2. 机制：三步

1. **条件编码**：条件信号 `c`（另一个模态、另一个通道、或某个先验量）过一个**很小的网络**，输出两组向量 `γ` 和 `β`，各 `C` 维（`C` = 主干特征通道数）。
2. **广播**：`γ`、`β` 沿时间轴和频率轴广播成和主干特征同形状。
3. **逐通道仿射**：`h' = γ ⊙ h + β`（`⊙` 为逐元素乘）。

**输出与输入形状完全相同**——所以它是"插件"式的，能塞进任意骨干的任意一层，不需要改下游结构。

### 3. 为什么便宜（这才是关键）

| | 参数量 | 机制 |
|---|---|---|
| **并行编码器 + 拼接 / 注意力** | 一整个编码分支（可能几万到几十万参数） | 第二路信号**自己生成一份特征**，再与主干特征对齐/融合 |
| **FiLM** | **仅 2C 个标量** | 第二路信号**不生成特征**，只生成"怎么缩放平移主干特征"的指令 |

`2C` 这个数字很关键：通道数通常是几百，所以 FiLM 头往往只有**几万个参数甚至更少**，而它替代的是一整条编码分支。

**实证（LAU-NetV2, INTERSPEECH 2026）**：把加速度计信号用 FiLM 压成 **VAD + 谐波两类线索**，开销约 **30k 参数**，替代了原先的并行编码器，PESQ 从 **1.78 → 2.78**；对比更早方案参数量减少约 **68×**。

### 4. 三个容易搞混的点

- **不是注意力机制。** 注意力是"按相关性加权求和"，权重是**数据相关的、逐位置**的；FiLM 是**逐通道的固定仿射**，同一通道在整个时间轴上共享同一个 `γ`。更便宜，表达力也更受限。
- **不是归一化层。** 虽然形式上都长 `γ·x + β`，但 BatchNorm/LayerNorm 的 `γ`、`β` 是**训练出来的静态参数**；FiLM 的 `γ`、`β` 是**由条件信号实时算出来的动态参数**。这是本质区别。
- **不是拼接 (concatenation)。** 拼接要求两路特征**在同一个特征空间、同一套形状**上对齐，代价是维度膨胀；FiLM 不需要对齐，只要求"能算出 C 维参数"。

### 5. 在低延迟 / 多通道场景下为什么特别合适

1. **参数量与 MACs 都低**——低延迟方向算力预算极紧，FiLM 头本身几乎不占预算。
2. **不改变主干形状**——骨干可以完全不动（甚至可以用现成的预训练骨干），只在中间插调制层。
3. **天然适合"先验 / 辅助信号"**：DOA、VAD 概率、SNR 估计、另一个模态——这些量**本来就不需要重建一份完整特征**，只需要告诉主干"现在该往哪个方向调"。
4. **可插拔**：LAU-NetV2 之外，HALO 这类"因果插件"式设计思路是同一哲学——**用一个小模块改主干的行为，而不是重训主干**。

### 6. 局限（论文没强调但要知道）

- **表达力有上限**：逐通道仿射是**一阶线性**的，如果第二路信号与主干特征的关系本质上是非线性的、或需要空间对齐（比如需要知道"哪个时频点是哪个方向"），FiLM 表达不了。
- **`γ`、`β` 的估计质量决定一切**：如果条件编码器本身很差（比如 DOA 在混响下不准），FiLM 会把错误放大到整条通道上。
- **不解决时序对齐问题**：条件信号与音频帧之间的时间对齐需要单独处理。
