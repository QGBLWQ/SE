# RNNoise vs Conv-TasNet — 两种设计哲学的对话

> 2018-2019 是语音增强/分离领域最精彩的两年。RNNoise 代表"极简 DSP+DL 混合"，Conv-TasNet 代表"纯 DL 端到端"。它们同年相邻，走向了完全相反的方向，却共享同一个核心操作——掩蔽 (masking)。

---

## 一、核心分歧：信号应该在哪个"域"处理？

这是最根本的分歧，一切后续设计都由此展开：

```
RNNoise 的信念：                    Conv-TasNet 的信念：
                                    
"STFT 是好的。                      "STFT 是不够好的。
 语音增强本来就是    
 频域操作——噪声和语音                STFT 是通用变换，不是
 在频谱上的分布不同，                为语音分离优化的。
 我们只需要在频域上                   
 做乘法（masking）。                 网络应该自己学一个
                                    更好的表示空间。
 问题只是：频点太多了
 → 压缩成 Bark 频带就好。"             让数据决定什么样的
                                     分解最利于分离。"
```

一张图说清：

```
同一个操作——掩蔽——作用在不同的"域"上：

RNNoise (2018):                       Conv-TasNet (2019):

波形                                  波形
  │                                     │
  ▼ STFT (固定)                         ▼ Conv1D (可学习)
  │                                     │
频谱图 [960 bins × T]                  隐空间 [512 dim × T]
  │                                     │
  ▼ Bark降维 (固定)                     │ (不需要降维——
  │                                      │  512 维已经够)
Bark 频带 [22 bands × T]               │
  │                                     │
  ▼ GRU → 估计 22 个增益                ▼ TCN → 估计 C×512 个权重
  │                                     │
  ▼ 插值回 960 bins                     ▼
  │                                     │
  ▼ × 频谱 (幅度掩蔽)                    ▼ × 隐空间特征 (特征掩蔽)
  │                                     │
  ▼ iSTFT (固定)                        ▼ Conv1D 转置 (可学习)
  │                                     │
增强语音                               分离语音 A, B, C
```

## 二、同一个 DNA — 掩蔽操作是两篇论文的公约数

尽管路线截然不同，两篇论文的核心操作完全一致：

| 操作 | RNNoise | Conv-TasNet |
|------|---------|-------------|
| **掩蔽公式** | $r(k) = \sum_b w_b(k) \hat{g}_b$ | $\mathbf{d}_i = \mathbf{w} \odot \mathbf{m}_i$ |
| **掩蔽值域** | $[0, 1]$ | $[0, 1]$ |
| **掩蔽含义** | "这个频带保留多少" | "这个特征维度保留多少" |
| **网络输出** | 22 个增益 + 1 个 VAD | C 组 × 512 维 mask |
| **激活函数** | Sigmoid | Sigmoid |
| **训练目标** | 自定义感知损失 | SI-SNR |

> **掩蔽 (masking) 是这个领域的万能接口。** 不管你在什么域处理——STFT 频域、Bark 频带、学习到的隐空间——"估计一个 0~1 的权重然后乘上去"这个操作本身就是最自然的分离范式。因为分离本质上就是"选择性地保留某些成分"，而乘法是最直接的实现。

## 三、设计哲学的逐项对比

### 3.1 谁来决定"特征是什么"？

| | RNNoise | Conv-TasNet |
|---|---------|-------------|
| **特征设计者** | 👨‍🔬 人类工程师 | 🤖 神经网络 |
| **特征类型** | BFCC + Δ + Δ² + pitch | 512 维自动学习的基函数 |
| **设计依据** | 声学/听觉理论 | 端到端梯度优化 |
| **可解释性** | ✅ 高（"这个特征就是低频能量"） | ❌ 低（"这个维度是什么？说不清"） |
| **泛化保证** | 理论上有保证 | 依赖训练数据覆盖 |

**为什么 RNNoise 选手工特征？** 因为网络只有 215 个单元——没有多余的容量去"学怎么表示声音"。必须把输入预处理成最利于学习的形态。

**为什么 Conv-TasNet 敢让网络自学？** 因为 TCN 有 5.1M 参数——有足够的容量去同时学习"怎么表示声音"和"怎么分离声音"。

### 3.2 谁来决定"分辨率"？

| | RNNoise | Conv-TasNet |
|---|---------|-------------|
| **频带/维度数** | 22 个 Bark 频带 | 512 维（≈23× RNNoise） |
| **分辨率设计依据** | 人耳临界频带 | 网络自动收敛 |
| **粗粒度的代价** | 谐波间噪声无法消除 | — |
| **粗粒度的补偿** | **Pitch 梳状滤波器** | 不需要补偿 |
| **段长** | 20ms（960 samples @48kHz） | **2ms（16 samples @8kHz）** |

两人走了完全相反的路：
- RNNoise：**长窗（20ms）+ 粗频带（22）**，需要额外 DSP 模块弥补
- Conv-TasNet：**超短窗（2ms）+ 细维度（512）**，信息足够就不需要弥补

Conv-TasNet 的 2ms 窗长是一个被低估的创新：如果让你手工设计 2ms 窗的特征你会设计什么？很难。但网络自己学到了有意义的基函数。

### 3.3 相位处理

| | RNNoise | Conv-TasNet |
|---|---------|-------------|
| **相位策略** | **完全不管** | **隐式编码在特征中** |
| **只改什么** | 幅度 | 整个特征向量 |
| **为什么这样** | 相位太敏感，随便改会失真 | 编码器基函数显式包含不同相位（论文 Fig 5） |

这是 Conv-TasNet 超越 ideal mask 的核心原因：

```
STFT 域的问题：
  X = |X| · e^{jφ}
  理想掩蔽只改了 |X|，φ 保持混合信号的相位
  → 即使 |X| 完美，φ 不对 → 重建有失真

Conv-TasNet 的解法：
  编码器输出 w 是 512 维实数向量
  它把相位信息"分散编码"到了 512 个维度中
  mask 操作同时影响幅度和相位等价信息
  → 不再存在"相位修复"这个独立问题
```

**RNNoise 为什么不处理相位？** 因为它的目标不是完美重建，而是"听起来好就行"。Bark 频带增益对相位的间接影响很小，而加上相位处理会显著增加复杂度——不符合"极简"哲学。

### 3.4 复杂度哲学：够用就好 vs 能好就好

```
                    RNNoise                 Conv-TasNet
                    
复杂度 (Mflops):    ██ 40                   ████████████ (估算 >500)

参数量:             ██ 87K                  ████████████████████ 5.1M

能跑在:             🥔 树莓派/嵌入式         💻 手机/桌面CPU

设计目标:           "最小化到极致"           "性能推到极致"
                    不浪费一个神经元         不放过 0.1 dB 的提升
```

Conv-TasNet 其实也是"高效"的——5.1M 参数在 2019 年的分离模型里是最小的（对比 uPIT-BLSTM 的 92.7M）——但它的"高效"是相对其他 DL 方法而言的。跟 RNNoise 比，它是 60 倍的参数量。

> 两者都是各自范式里的"效率冠军"：RNNoise 是 DSP+DL 混合方法中最小的，Conv-TasNet 是纯 DL 端到端方法中最小的。

### 3.5 记忆机制：循环 vs 并行

```
RNNoise (GRU):                         Conv-TasNet (TCN):

时间 →                                时间 →
t=1 ●                                  t=1 ●
    ↓                                       ↓ d=1
t=2 ● (必须等 t=1 算完)                t=2 ● (所有 t 同时算)
    ↓                                       ↓ d=2
t=3 ● (必须等 t=2 算完)                t=3 ● (跳1格看)
    ↓                                       ↓ d=4
t=4 ● (必须等 t=3 算完)                t=4 ● (跳3格看)

优点: 理论无限记忆                    优点: 所有时间步并行
      参数量极少                            训练快
      天然因果                              对起始点鲁棒

缺点: 必须顺序计算                    缺点: 固定感受野
      容易梯度消失                         参数量大
      对起始点敏感                         需要更长上下文时得重新设计
```

### 3.6 损失函数：感知优先 vs 指标驱动

| | RNNoise | Conv-TasNet |
|---|---------|-------------|
| **损失函数** | $L = (g_b^\gamma - \hat{g}_b^\gamma)^2$, $\gamma=1/2$ | SI-SNR |
| **设计理念** | "数值最优 ≠ 听感最优" | "直接在目标指标上优化" |
| **对静音的处理** | 显式 mask 掉无定义区域 | SI-SNR 自带零均值归一化 |
| **知识来源** | 声学感知经验 | 端到端梯度 |

## 四、它们分别回答了什么根本问题？

```
RNNoise (2018) 在问：                  Conv-TasNet (2019) 在问：

"一个实时语音增强系统，                 "语音分离的精度上限在
 可以有多小？                          哪里？STFT 域的天花板
                                      能被打破吗？"
 答案：87K 权重，40 Mflops，
 树莓派上跑 48kHz。                     答案：天花板是 STFT 本身
                                      造成的。换一个域，就能
                                      超过 oracle mask。
```

两篇论文都没有回答的问题（留给了后来者）：

| 问题 | 谁回答了？ |
|------|-----------|
| 时域方法怎么做到 48kHz 全频带？ | DPRNN (2020), SepFormer (2021) |
| 频域方法怎么显式处理相位？ | DCCRN (2020), PHASEN (2020) |
| 极简方法怎么引入感知度量？ | PercepNet (2020) — Valin 自己的改进 |
| 时域方法怎么做到更低复杂度？ | 还在等 |

## 五、如果你只能带走一个洞察

> **RNNoise 和 Conv-TasNet 的本质区别，不是"传统 vs 深度"、"频域 vs 时域"、"GRU vs TCN"——而是对"好的表示从哪里来"这个问题的不同答案。**

```
RNNoise 相信：                     Conv-TasNet 相信：

"好表示来自于                       "好表示来自于
 人类对信号的理解                    数据的自我组织
 + 声学/听觉理论                    + 梯度下降
 + 精心设计的降维"                   + 足够容量"
```

两篇论文都在 2018-2019 年取得了各自范式下的最好结果。这说明：**在当下，两种路线都有效——选择哪条取决于你的约束条件（算力、延迟、数据量、应用场景），而不是一条路"对了"另一条"错了"。**

真正的分野在于：RNNoise 已经几乎是它那条路的"终点了"——把手工特征+RNN 压缩到了极限，再往下优化的空间很小。而 Conv-TasNet 打开了一扇新门——"让网络自学表示"——这扇门后面涌现了 DPRNN、SepFormer、TF-GridNet 等一系列更强的系统。
