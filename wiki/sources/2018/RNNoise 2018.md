# RNNoise — A Hybrid DSP/Deep Learning Approach to Real-Time Full-Band Speech Enhancement

> Jean-Marc Valin, Mozilla Corporation, 2018

## 1. 动机：他们为什么这么做？

传统语音噪声抑制器（如 SpeexDSP）依赖一套手工调参的信号处理管线：**VAD**（语音活动检测）→ **噪声谱估计** → **谱幅度估计** → **增益计算**。其中每个估计器都需要针对特定噪声场景做启发式调参，**泛化能力差**，尤其在**非稳态噪声**（如 babble、键盘声）下表现糟糕。

与此同时，2016-2017 年深度学习开始在语音增强领域崭露头角，但当时的 DL 方案存在一个致命问题：

| 方法                        | 计算量                       |     能否实时 CPU？     |
| ------------------------- | ------------------------- | :---------------: |
| Mirsamadi & Tashev (2016) | 1600 Mflops + 800 MB/s 带宽 |         ❌         |
| 端到端 DNN 波形生成              | 更高                        |         ❌         |
| **RNNoise 目标**            | **≈ 40 Mflops**           | **✅ 树莓派 14% CPU** |

Valin 的洞察是：**不必端到端替代整个管线**。传统 DSP 管线中，STFT/iSTFT 是数学完备的，Pitch 检测是成熟的信号处理问题——只有那三个**估计器**（VAD、噪声谱、谱幅度）是"暗黑艺术"（dark art），最适合用神经网络替代。这种"精准打击"的混合哲学，比端到端方案更务实。

## 2. 前人局限：之前的人怎么做不了？

**Gap 的本质**：在 2018 年之前，没有人能在 48 kHz 全频带、< 10 ms 延迟、低功耗 CPU（无 GPU）的约束下，用深度学习方法做语音增强。这个 gap 之所以存在，有三重原因：

1. **频带维数灾难**：48 kHz 全频带 STFT 产生 480+ 个频率 bin，直接让网络输出 480 维增益 → 网络规模爆炸
2. **实时 CPU 推理的算力墙**：2016 年的 DL 降噪方案需要 1600 Mflops，比 RNNoise 的 40 Mflops 高 **40 倍**
3. **全频带数据与标注困难**：48 kHz 的干净语音和噪声配对数据稀缺，合成数据的分布匹配也是挑战

前人尝试过的路径及其失败原因：
- **纯 DSP 方法**（MMSE 估计器）：非稳态噪声场景下性能急剧退化
- **DL 端到端**（Mirsamadi 2016）：算力要求过高，无法实时
- **窄带/宽带 DL**（16 kHz 以下）：无法利用高频信息（8-20 kHz），语音自然度受限

RNNoise 的破局之道在于一个反直觉的设计：**用 22 个 Bark 频带代替 480+ 个频率 bin 作为网络输出**。这一降维操作将输出空间缩小了 20+ 倍，使得轻量网络成为可能。而 Bark 频带分辨率不足的问题，则通过后级的 **Pitch 梳状滤波器**（纯 DSP）来弥补——这又回到了混合架构的核心哲学。

## 3. 核心 Trick：这个做法关键在哪？

如果只挑**一个最关键的设计**，是 **Bark 频带降维 + Pitch 滤波器两级抑制**的组合：

```
粗粒度: RNN → 22 Bark 频带增益 → 抑制噪声的整体频谱包络
细粒度: Pitch 梳状滤波器 → 消除谐波之间的残余噪声
```

但完整回答需要列出所有重要 trick 并区分主次：

| 优先级 | Trick                                         | 作用                     | 如果没有会怎样                          |
| :-: | --------------------------------------------- | ---------------------- | -------------------------------- |
| ⭐⭐⭐ | **Bark 频带降维** (480+ bin → 22 band)            | 将网络输出空间缩小 20+ 倍        | 网络规模至少 5-10× 增大，无法在 ARM CPU 上实时  |
| ⭐⭐⭐ | **Pitch 梳状滤波器**                               | 消除谐波间噪声（Bark 频带分辨率不够）  | 谐波间残留噪声明显，语音有"水声"感               |
| ⭐⭐  | **感知加权损失** (γ=1/2, 非交叉熵)                      | 交叉熵不匹配增益的感知效果；γ→0 过度抑制 | 用交叉熵 → 频带增益不平滑；用对数 MSE → 语音被过度压制 |
| ⭐⭐  | **保留第一阶 cepstral 系数** (不做 cepstral mean norm) | 保留噪声绝对水平信息，辅助 VAD      | 对输入增益敏感，需数据增强补偿                  |
|  ⭐  | **8-bit 权重量化**                                | 全部 87K 权重放入 L2 Cache   | 无量化也可运行，但 cache miss 增加          |
|  ⭐  | **GRU 而非 LSTM**                               | 效果相当但更简单               | 用 LSTM 参数略多，但差异不大                |
|     |                                               |                        |                                  |

**深层洞察**：三层 GRU 在网络结构上恰好对应传统管线中的三个估计器（VAD → 噪声估计 → 谱估计），这种"结构先验"让网络不需要从零学习信号处理流。

## 4. 消融分析：哪个设计最敏感？

> ⚠️ **重要说明**：RNNoise 论文**没有提供正式的消融实验**（没有逐模块拆除的性能对比表格）。以下分析基于论文中的定性描述和技术推演。

**论文中唯一可视为"消融"的对比**：

| 对比项 | 效果 |
|--------|------|
| 有 Pitch 滤波器 vs 无 | 谐波间噪声可闻 vs 不可闻（定性） |

**根据设计推断的敏感度排序**（高→低）：

1. **Pitch 滤波器** — 最敏感。Bark 频带只有 22 个，低频段每个频带覆盖多个谐波。不加 pitch 滤波器 → 谐波间噪声完全无法处理 → 语音有"水声"伪影
2. **Bark 频带数量** — 高度敏感。减少 → 频带分辨率不够，谐波失真增加；增加 → 网络规模膨胀。22 是精心选择的甜点
3. **γ 参数（感知加权指数）** — 中度敏感。γ=1/2 是经验选择；γ→0 (对数域) → 过度抑制，语音沉闷；γ→1 (线性域) → 抑制不足
4. **帧间增益平滑 (λ=0.6)** — 低度敏感。影响输出自然度但不影响核心降噪能力；λ 太小 → 输出"过干"；λ 太大 → 噪声衰减速度慢

**最大遗憾**：论文没有报告以下消融，而这些对理解方法至关重要：
- RNN 网络大小 vs 性能的关系（215 单元是否过度参数化？）
- 三层 GRU vs 更少层数的对比
- 不使用 BFCC 差分特征（只用静态特征）的性能损失
- Pitch 特征对 VAD 辅助输出的贡献

## 5. 遗留问题：还剩什么没解决？

### 论文自己承认的局限

1. **α_b 的启发式设计** (Eq. 6)：Pitch 滤波器系数来自经验约束，无法推导理论最优值，对不同 pitch 强度可能不够鲁棒
2. **缺少全频带主观 MOS**：PESQ 仅支持 16 kHz 以下，48 kHz 全频带的实际听感提升未被量化
3. **VAD 辅助输出**：训练方式和对最终质量的定量贡献未详述

### 读出来的隐藏问题

4. **标量增益的固有限制**：RNNoise 输出的是每个频带的标量增益 $\hat{g}_b$，只能调整幅度，**无法处理相位**。在低 SNR 或强混响场景下，相位失真成为瓶颈 → 这直接催生了后来的 [[DeepFilterNet]] 方向（用复数域深度滤波替代标量增益）
5. **Pitch 滤波器对非谐波语音失效**：清音（unvoiced speech，如 /s/, /f/）没有谐波结构，pitch 滤波器完全无效，只能依赖粗粒度的 Bark 增益
6. **训练数据多样性有限**：6 小时语音 + 4 小时噪声，虽然通过增强扩展到 140 小时，但语言/说话人/声学环境的覆盖仍有限
7. **无混响处理**：论文场景是视频会议（近场麦克风），不涉及去混响，无法直接用于远场场景
8. **Bark 频带的刚性限制**：22 个固定频带无法自适应调整——某些噪声可能需要更细的频率分辨率

### 这些 gap 如何被后续工作填补

| Gap           | 填补工作                     | 年份        |
| ------------- | ------------------------ | --------- |
| 启发式 pitch 滤波器 | [[PercepNet]] 用感知模型替代    | 2020      |
| 标量增益 → 复数滤波   | [[DeepFilterNet]] 用深度滤波  | 2021-2023 |
| 有限训练数据        | 大规模预训练 + 泛化评估            | 2021+     |
| 无混响处理         | [[DeepFilterNet]] 等支持去混响 | 2022+     |

## 一、研究任务与对象

| 维度 | 详情 |
|---|---|
| **任务** | 语音增强 / 噪声抑制 (Noise Suppression) |
| **目标场景** | 视频会议等实时通信 (real-time, full-duplex) |
| **采样率** | 48 kHz 全频带 (0–20 kHz) |
| **延迟** | 20 ms 窗 + 50% 重叠 = 10 ms 帧移，低延迟 |
| **硬件约束** | 低功耗 CPU，无需 GPU；目标嵌入式/移动设备 |

**核心设计思想**：用深度学习**只替代**传统噪声抑制管线中难以调参的估计器（VAD、噪声谱估计、谱幅度估计），其他信号处理部分保留传统 DSP 方法。这种"混合"思路与端到端 (end-to-end) 方案形成鲜明对比。

## 二、技术路线

### 整体管线

```
Input → STFT → [Band Gain (RNN)] → [Pitch Filter] → iSTFT → Output
                ↑                    ↑
            Bark 频带增益         梳状滤波消除
           (粗粒度包络抑制)     谐波间噪声 (细粒度)
```

### 关键设计决策

| 决策 | 做法 | 动机 |
|---|---|---|
| **频带降维** | 22 个 Bark 尺度三角频带 | 避免 RNN 直接输出 400+ 频率 bin，大幅降低复杂度 |
| **输出目标** | 理想临界频带增益 $g_b = \sqrt{E_s(b)/E_x(b)}$ | 即 IRM 的平方根，值域 [0,1]，天然有界 |
| **网络规模** | 215 单元、4 隐藏层、最大层 96 单元 | 极轻量，8-bit 量化后全部权重可放入 L2 Cache |
| **粗+细两级抑制** | RNN 做 Bark 频带级粗抑制 + 梳状滤波器做谐波间的细抑制 | 弥补 Bark 频带分辨率不足的问题 |
| **不使用 cepstral mean normalization** | 保留第一阶 cepstral 系数 | 需要追踪噪声的绝对水平，但通过数据增强应对敏感性问题 |

### 特征提取（42 维输入）

| 特征 | 维度 | 说明 |
|---|---|---|
| BFCC（Bark 频率倒谱系数） | 22 | 对 22 个 Bark 频带的对数能量做 DCT |
| $\Delta$ BFCC | 6 | 前 6 个 BFCC 的一阶时间差分 |
| $\Delta^2$ BFCC | 6 | 前 6 个 BFCC 的二阶时间差分 |
| Pitch 相关性的 DCT 系数 | 6 | 跨频带的 pitch 相关性做 DCT，取前 6 个 |
| Pitch 周期 | 1 | 基音周期 T |
| 频谱非平稳性度量 | 1 | 辅助语音检测 |

### 神经网络架构

```
Dense(GRU(GRU(GRU(Dense(Input)))) → 22 gains + 1 VAD
                           ↑
                      VAD 辅助输出
```

- **GRU** 略优于 LSTM（更简单、效果相当）
- 三层 GRU 分别对应传统管线中的：VAD → 噪声估计 → 谱估计（设计假设，实际网络可自由偏离）
- 215 单元、87,503 权重

### Pitch 滤波器

频域梳状滤波器：基于 pitch 延迟 $T$，计算 $P(k)$（pitch 延迟信号的 DFT），每频带用滤波系数 $\alpha_b$ 对 $X(k) + \alpha_b P(k)$ 做滤波后重新归一化。

$\alpha_b$ 由启发式公式给出（Eq. 6），满足三个约束：
- $p_b \geq g_b$ 时 $\alpha_b = 1$（噪声导致 pitch 相关性下降时全力利用）
- $g_b = 1$ 时 $\alpha_b = 0$（无噪声不引入失真）
- $p_b = 0$ 时 $\alpha_b = 0$（无 pitch 不做增强）

## 三、关键公式

### Eq. 1 — Vorbis 分析/合成窗

$$w(n) = \sin\left[\frac{\pi}{2}\sin^2\left(\frac{\pi n}{N}\right)\right]$$

- 满足 Princen-Bradley 准则（完美重建条件）
- 窗长 $N$ = 20 ms × 48 kHz = 960 采样点
- 50% 重叠 → 帧移 10 ms

### Eq. 2 — Bark 频带能量

$$E(b) = \sum_k w_b(k) |X(k)|^2$$

- $w_b(k)$：频带 $b$ 在频率 $k$ 处的三角权重，$\sum_b w_b(k) = 1$
- 22 个频带覆盖 0–20 kHz，遵循 Bark 尺度（高频等带宽，低频至少 4 bin）

### Eq. 3 — 理想临界频带增益（核心输出目标）

$$g_b = \sqrt{\frac{E_s(b)}{E_x(b)}}$$

- $E_s(b)$：干净语音在频带 $b$ 的能量
- $E_x(b)$：带噪语音在频带 $b$ 的能量
- 本质是**理想比率掩蔽 (IRM) 的平方根**，值域 $[0, 1]$
- → 见 [[理想比率掩蔽 IRM]]

### Eq. 4 — 插值到频率 bin 的增益

$$r(k) = \sum_b w_b(k) \hat{g}_b$$

- 将 22 个频带增益 $\hat{g}_b$ 用同样的三角权重插值回每个频率 bin
- 保证频率域连续平滑

### Eq. 5 — 跨频带 Pitch 相关性

$$p_b = \frac{\sum_k w_b(k) \Re\left[X(k)P^*(k)\right]}{\sqrt{\sum_k w_b(k)|X(k)|^2 \cdot \sum_k w_b(k)|P(k)|^2}}$$

- $P(k)$：pitch 延迟信号 $x(n-T)$ 的加窗 DFT
- 对单个频带，等价于时域 pitch 相关性
- 用于判断每个频带是否存在周期性结构（谐波）

### Eq. 6 — Pitch 滤波器系数（启发式）

$$\alpha_b = \min\left(\sqrt{\frac{p_b^2(1-g_b^2)}{(1-p_b^2)g_b^2}},\ 1\right)$$

- 纯启发式设计：无法推导最优值，基于约束和观察
- 控制每个频带中利用 pitch 信息消除谐波间噪声的强度

### Eq. 7 — 数据增强：随机频率响应扰动

$$H(z) = \frac{1 + r_1 z^{-1} + r_2 z^{-2}}{1 + r_3 z^{-1} + r_4 z^{-2}}$$

- $r_i \sim \mathcal{U}[-\frac{3}{8}, \frac{3}{8}]$，每训练样本独立采样
- 让网络学习忽略绝对频率响应差异（因为没有使用 cepstral mean normalization）

### Eq. 8 — 感知加权损失函数

$$L(g_b, \hat{g}_b) = \left(g_b^\gamma - \hat{g}_b^\gamma\right)^2$$

- $\gamma = 1/2$：最小化能量 $^{1/4}$ 上的 MSE
- $\gamma \to 0$ 将退化为对数域 MSE → 过度抑制
- **不用交叉熵**：交叉熵不匹配增益的感知效果
- → 详见 [[感知加权损失函数]]

### Eq. 9 — 帧间增益平滑

$$\tilde{g}_b = \max\left(\lambda \tilde{g}_b^{(prev)},\ \hat{g}_b\right)$$

- $\lambda = 0.6$，等效混响时间 135 ms
- 只限制衰减、不限制上升（最大值操作），避免让输出听起来"过干"

## 四、结果与评估

### 复杂度分析

| 组件 | 计算量 |
|---|---|
| RNN 前向推理 | 17.5 Mflops |
| FFT ×2 + IFFT ×1 | 7.5 Mflops |
| Pitch 搜索 (12 kHz) | 10 Mflops |
| **总计** | **≈ 40 Mflops** |

| 平台 | 单通道 48kHz 占用 |
|---|---|
| x86 Haswell i7-4800MQ | **1.3%** 单核 |
| ARM Cortex-A53 1.2GHz (树莓派3) | **14%** |

对比：文献 [9]（Mirsamadi & Tashev, 2016）需 1600 Mflops + 800 MB/s 内存带宽。

### 质量评估（PESQ MOS-LQO）

使用训练集未见过的语音和噪声，对比 SpeexDSP 库的 MMSE 噪声抑制器：

- **非稳态噪声**（如 babble）：显著提升
- **稳态噪声**（如 car）：也有改善，但幅度较小
- 主观听感确认客观指标的趋势

> [!note] 评价指标局限
> PESQ 仅支持 16 kHz 以下的窄带/宽带评估，48 kHz 全频带输出需降采样后再评估。全频带的主观质量未量化。

| 维度 | 论文 | 关系 |
|------|------|------|

## 七、一句话总结“江湖地位”

> **2018 | 语音增强 | 首个实用级实时全频带混合 DSP-DL 噪声抑制器** → 以 87K 权重、40 Mflops 的极低代价，在树莓派上实现 48 kHz 实时降噪，证明了"精准替代而非端到端替代"的混合哲学在工业级应用中的可行性。
>
> **直接继承者**：[[PercepNet]] (2020, 同作者 Valin) — 用可学习的感知模型替代 RNNoise 中启发式的 Pitch 滤波器，进一步提升了非稳态噪声下的表现。
>
> **精神继承者**：[[DeepFilterNet]] (2021-2023) — 继承"小网络 + 感知动机"的设计哲学，但将标量 Bark 增益升级为复数域深度滤波，突破了 RNNoise 无法处理相位的根本局限。
>
> **历史定位**：RNNoise 不是精度最高的语音增强方法（被后续纯 DL 方法在指标上超越），但它是**第一个将 DL 降噪真正带入实时通信产品级别**的工作（Mozilla Firefox 集成、众多 VoIP 应用使用）。在混合 DSP-DL 这一分支中，它是**开山之作和基准线**，后续所有混合方法要么继承它、要么回应它。
>
> **对标关系**：如果 [[Conv-TasNet]] (2019) 代表"时域端到端分离"的极致精度路线，RNNoise 就代表"频域混合轻量"的极致效率路线——两者并列为语音增强领域两种对立设计哲学的旗帜性工作。
