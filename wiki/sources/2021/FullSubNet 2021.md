# FullSubNet: A Full-Band and Sub-Band Fusion Model for Real-Time Single-Channel Speech Enhancement

> Xiang Hao, Xiangdong Su, Radu Horaud, Xiaofei Li, ICASSP 2021 (DNS Challenge 冠军)

## 1. 动机：他们为什么这么做？

FullSubNet 的动机源于一个具体的技术矛盾：

**全带模型**（CRNN 等）：输入整个频谱 [F×T]，通过频率池化压缩到 F'=16-64 bin。好处是保留全局频谱结构（"低频有共振峰，高频有摩擦音"），代价是**频率分辨率被池化碾碎了**——一个池化后的 bin 覆盖几十个原始频率 bin，无法做精细的逐频率增益。

**子带模型**（频带 LSTM 等）：对每个频率 $f$，取左右 K 个邻居做独立的局部处理。好处是频率分辨率极高（每个 bin 一个专属增益），代价是**没有全局视野**——只知道"我周围 30 个 bin 在干什么"，不知道"整条频谱在干什么"。

FullSubNet 的洞察：

```
全带 = 看森林 (全局频谱结构: 语音在 300-3400 Hz, 噪声在高频)
子带 = 看树木 (局部细节: 这个 bin 是语音谐波的峰还是谷)

级联: 先用全带看清"哪片森林里有语音" → 告诉子带 → 子带在指定的区域做精细砍伐
```

这和 DPRNN 的"块内+块间"是同一个范式——**只是在频率维做分解，而非时间维**。

## 2. 前人局限：之前的人怎么做不了？

**Gap 的本质**：在 FullSubNet 之前，全带和子带是两条**并行不交叉**的研究线。

| 研究线 | 代表 | 做了什么 | 没做什么 |
|--------|------|---------|---------|
| **全带模型** | CRNN (2018-2020) | Conv2D 降采样 + RNN → 全局频谱建模 | 频率池化丢失细节 |
| **子带模型** | 子带 LSTM (2019) | 对每个频率独立处理 → 精细增益 | 无跨频带视野 |
| **全带 → 子带级联** | — | **没有人做过** | — |

为什么没人做？两个障碍：

1. **效率恐慌**：子带模型需要**对每一个频率 bin 跑一次 LSTM**——257 个频率 bin = 257 次 LSTM 前向传播。看起来不可行。但 FullSubNet 证明了"加了全带特征引导之后，子带 LSTM 可以做得很小（单层 128 单元），总推理时间仍然可控"
2. **架构设计空白**：如何把全带特征"喂给"子带？直接 concat？做 attention？还是其他？没有现成配方。FullSubNet 的级联方案（全带输出插值到每个频率 → 作为子带 LSTM 的额外输入）是经过消融验证的最优方式

## 3. 核心 Trick：这个做法关键在哪？

FullSubNet 的方法体系中有三个层级的设计决策，重要性递减：

| 优先级 | Trick | 作用 | 如果没有会怎样 |
|:---:|------|------|------|
| ⭐⭐⭐ | **全带→子带级联（非并行）** | 全带特征作为子带的"注意力引导"——告诉子带每个频率的全局语境 | 并行融合 → 信息交换不如级联充分 → PESQ 下降 |
| ⭐⭐ | **子带滑动窗口** | 频率 $f$ 的子带输入 = $[f-K, f+K]$ 的帧序列 → 局部频谱模式可被 LSTM 学习 | K=0 → 只看一个 bin → 无法识别谐波/共振峰 → 性能崩塌 |
| ⭐⭐ | **全因果架构** | Conv2D 用 causal padding + uni-LSTM 替代 Bi-LSTM → 实时 16ms 延迟 | 用非因果 → 需要看未来帧 → 延迟增加 → 无法实时 |
| ⭐ | **全带频率降采样策略** | 池化从 F=257 降到 F'=64（而非 SELDnet 的 F'=2）→ 保留足够频率结构 | F'=16 → 全局信息过粗 → 子带得不到有效引导 |

**与 DPCRN 的"分工"对比——不同维度，同一哲学：**

```
DPCRN (2021):  时间维分解  → 块内局部 + 块间全局
FullSubNet (2021): 频率维分解 → 子带局部 + 全带全局
                ↑ 同年同哲学，但从未做过正面比较！
```

## 4. 消融分析：哪个设计最敏感？

| 消融项 | 效果 | 结论 |
|--------|------|------|
| 完整 FullSubNet | **best** | baseline |
| 仅全带 (无子带) | 全局结构好，局部细节模糊 | 全带单独不行——丢频率细节 |
| 仅子带 (无全带) | 局部精确，缺少跨频带协同 | 子带单独不行——无全局视野 |
| 全带+子带并行融合 | 不如级联 | **级联 > 并行**——信息从粗到精的流向是关键 |
| 子带窗口 K=5 | 上下文不够 | 邻频信息不足 → 谐波/共振峰识别困难 |
| 子带窗口 K=15 | **甜点** | 覆盖足够宽（31 个相邻频带≈1.9 kHz @16kHz） |
| 子带窗口 K=30 | 收益递减 | 更宽 → 计算量大增，性能几乎不增 |

**最敏感的维度（从消融推演）：**

1. **全带 vs 子带 = 缺一不可** — 最敏感。丢掉任何一半都会导致特定频率范围的性能崩塌
2. **级联 vs 并行** — 中度敏感。信息从粗到精的流向比双向交换更有效（和 PHASEN 的 FTB 双向融合形成对比——PHASEN 的幅度和相位需要双向，FullSubNet 的全带→子带只需要单向，因为全带信息天然是子带的"上下文"而非"对话对象"）
3. **子带窗口大小** — K=15 是最优经验值，但论文未给出 K 的精确敏感度曲线
4. **全带降采样后 F' 的大小** — F'=64 > F'=16 → 全局信息的频率分辨率越高越好

**论文没有报告的消融：**
- 全带用 Bi-LSTM vs uni-LSTM 的对比（实时约束下的性能损失）
- 子带 LSTM 的层数/单元数敏感度
- 不同频率区域的子带 LSTM 是否应该共享参数？（论文共享了——低频和高频用同一个 LSTM——这可能限制了性能）

## 5. 遗留问题：还剩什么没解决？

### 论文自己承认的局限

1. **幅度-only + 带噪相位**：不处理相位 → 和 DCCRN/PHASEN 相比有固有劣势
2. **子带逐频率处理 = 推理瓶颈**：257 次 LSTM 调用/帧 → 后续 Fast FullSubNet (2023) 将其降低到 13%，但代价是精度小幅下降

### 读出来的隐藏问题

3. **"频率分治 vs 时间分治"的正面比较从未发生**：FullSubNet (频率维分解) 和 DPCRN (时间维分解) 是同年、同任务、同水平的两个方法——但没有人做过公平消融对比。哪个维度的分解更有效？两者是否可以叠加？完全空白
4. **子带 LSTM 共享参数可能限制了高频性能**：低频（0-2 kHz）和高频（6-8 kHz）的子带特征完全不同——谐波结构 vs 摩擦音噪声——共享同一个 LSTM 意味着两个场景在争抢模型的表示空间
5. **全带特征注入方式过于简单**：current 方案是直接 concat——如果改成 cross-attention（像 PHASEN 的 FTB），全带特征可以动态决定"每个频率 bin 需要多少引导"，可能更有效
6. **DNSMOS 和 PESQ 不直接可比**：论文在 DNS Challenge 集上用 DNSMOS 评估，在 Voice Bank+DEMAND 上用 PESQ——两组指标不能直接翻译，和 DCCRN 的对比不精确
7. **相位感知版的 FullSubNet 是空白**：如果用复数频谱替代幅度谱、cIRM 替代标量 mask、全带和子带都用复数 LSTM → "Complex FullSubNet"——一个显而易见的扩展但没有人做过

### 这些 gap 如何被后续工作填补

| Gap         | 填补工作                                          | 年份   |
| ----------- | --------------------------------------------- | ---- |
| 频率分治 → 三维分治 | [[CST-former 2025]] 将全带-子带的 1 维分解推广到 C+S+T 三维 | 2025 |
| 推理加速        | Fast FullSubNet (计算量降至 13%)                   | 2023 |
| 相位感知        | 完全空白 — ⚠️ Complex FullSubNet 未被探索             | —    |

## 二、技术路线

### 核心公式

子带模型对频率 $f$ 的增益预测：

$$\hat{M}_f = \text{SubLSTM}\left(X_{[f-K, f+K]},\ h_f^{\text{global}}\right)$$

其中 $X_{[f-K, f+K]} \in \mathbb{R}^{(2K+1) \times T}$ 是频率 $f$ 左右各 K 个邻居的 T 帧序列，$h_f^{\text{global}}$ 是全带模型在频率 $f$ 处的插值特征。

### 架构概览——模拟一次前向传播

以真实参数模拟（16 kHz, 20ms 窗/10ms 帧移/320-FFT → 补零到 512）：

```
输入: 带噪语音 → STFT 幅度谱
  ├── F = 257 bins (0–8 kHz, 512-FFT 取一半+1)
  ├── T 帧 (实时, 持续输入)
  └── 形状: [T, 257]

═══════════════════════════════════════════
分支 1: 全带模型 (Global Full-Band Branch)
═══════════════════════════════════════════

▸ Conv2D Encoder (频率维降采样):
  L1: [T, 257] → Conv2D(3×1, s=2) → [T, 129, 16]
  L2: [T, 129, 16] → Conv2D(5×1, s=2) → [T, 65, 32]
  L3: [T, 65, 32] → Conv2D(5×1, s=2) → [T, 33, 64]
  L4: [T, 33, 64] → Conv2D(5×1, s=1) → [T, 33, 64]
  输出: [T, 33, 64]
  ↑ F=257 → 33 (≈8× 压缩)

▸ 因果 LSTM:
  每个时间帧 t: [33, 64] → fc → [33, 256] → uni-LSTM(256)
  → h_t^full [33, 256]
  ↑ 注意: 是因果 LSTM (非 Bi-LSTM)，不偷看未来帧

▸ 频率维插值:
  h_t^full [33, 256] → 插值回原始频率分辨率 → h_t^global [257, 256]
  ↑ 从 33 个频带插值回 257 个频带——每个原始频率 f 得到一个 256 维全局特征

═══════════════════════════════════════════
分支 2: 子带模型 (Local Sub-Band Branch)
═══════════════════════════════════════════

▸ 对每个频率 f = 0, 1, ..., 256:

  a) 取子带输入:
     从幅度谱 [T, 257] 中取第 [f-15, f+15] 列 (31 个相邻频率 bin)
     → X_f [T, 31]
     ↑ K=15, 覆盖 31×31.25Hz ≈ 969 Hz 的局部频带

  b) 拼接全带特征:
     X_f [T, 31] ⊕ h_t^global[f, :] [T, 256]
     → 输入: [T, 287]   (31 局部 + 256 全局)
     ↑ 全带特征告诉子带:"你在 3kHz 附近 → 语音在这里 F3/F4 共振峰区"

  c) 子带 LSTM:
     [T, 287] → fc([287, 128]) → uni-LSTM(128) → fc([128, 1])
     → output: â_f [T]  (频率 f 在所有帧上的增益)
     ↑ 单层 128 单元，极轻量

  d) sigmoid: ĝ_f = sigmoid(â_f) ∈ [0, 1]

  所有频率并行处理 (或按批处理)
  → 最终输出: mask [T, 257]

═══════════════════════════════════════════
应用 + 后处理
═══════════════════════════════════════════

  Ŝ_mag = mask ⊙ |X|             ← 逐 bin 乘
  带噪相位 φ_X 保持不变
  iSTFT(Ŝ_mag · e^{jφ_X}) → 增强波形

═══════════════════════════════════════════
参数量分解
═══════════════════════════════════════════

  全带: Conv2D + LSTM + 插值层 ≈ 1.5M
  子带: 输入 fc(287→128) + LSTM(128) + 输出 fc(128→1)
        ≈ 每个频率 55K × 257 个频率 = 共享参数后 ≈ 4.1M
  总计: ≈ 5.6M

  推理时间分解 (单帧, CPU):
  全带: ~2ms  (一次前向)
  子带: ~12ms (257 次 LSTM, 但单元极小)
  总计: ~14ms < 16ms 帧移 ✅ 实时
```

## 三、关键结果

| 方法 | DNSMOS | PESQ | 参数量 | 实时? |
|------|:------:|:----:|:------:|:---:|
| Noisy | 2.85 | 1.97 | — | — |

## 六、一句话总结“江湖地位”

> **2021 | 语音增强 | 频率维"分而治之"的开创者 + DNS Challenge 冠军** → FullSubNet 证明了全带（全局频谱结构）和子带（局部频率细节）融合的价值，以 5.6M 参数、全因果 14ms 延迟，实现了实时场景下的高质量语音增强。和同年 [[DPCRN 2021]] 并列代表了"分而治之"范式在两个不同维度上的成功实践——FullSubNet 在频率维做分解，DPCRN 在时间维做分解。
>
> **直接继承者**：Fast FullSubNet (2023) 将推理加速到 13%（通过剪枝 + 知识蒸馏），Spiking-FullSubNet (2024) 用脉冲神经网络进一步降低能耗。
>
> **精神继承者**：[[CST-former 2025]] — 将 FullSubNet 的 1 维频率分解推广到 3 维（通道+频谱+时间），用独立的多头注意力替代全带 CRNN + 子带 LSTM 的组合。
>
> **历史定位**：FullSubNet 是"频率分治"这一范式在语音增强中的方法基准——它和 DPRNN 的"时间分治"共同构成了"分而治之"思想的两个正交实现。它也是 DNS Challenge 社区的实际 baseline（2021-2023 年间几乎所有参赛系统都在它的基础上改进）。
>
> **未竟之业**：频率分治 × 时间分治 × 复数网络 = **三维分治 + 相位感知**——将 FullSubNet 的全带-子带分解推广到复数域，再叠加上双路径的时间维分治，可能是同时解决频率分辨率、长序列建模和相位保真度的终极方案。目前无人尝试。
