# STFT 与频谱图 — 语音增强的"像素化"表示

## 用一张图说清楚

语音增强领域最常见的操作就是把声音从"波形"变成"频谱图"，处理完再变回去。为什么？

```
原始音频（时域波形）：           频谱图（时频域）：
                        
  ╱╲  ╱╲                     频率↑
 ╱  ╲╱  ╲    ╱╲              │  ░░░░████░░░░░░░░
╱        ╲  ╱  ╲             │  ░░████████░░░░░░
          ╲╱    ╲  时间→     │  ██████░░████░░░░
                             │  ░░░░░░░░████████   时间→
  只能看到幅度变化               ├──────────────┤
  看不到频率组成                 可以看到"哪个频率在哪个时刻有多强"
```

## 核心思想：短时傅里叶变换 (STFT)

### 为什么不能直接对整个音频做 FFT？

FTT 会假设信号是**周期性的且不随时间变化**。但语音是快速变化的——0.1 秒前说的是"a"，0.1 秒后变成"o"。直接对整个 5 秒音频做 FFT，会把所有时间信息混成一锅粥。

### 解决办法：切成小片，逐片分析

```
原始信号: [a a a a o o o o e e e e ...]
         ↓ 切窗 (20ms = 960 samples)
  窗1: [a a a a]
  窗2:   [a a a o o]  ← 重叠50%，窗慢慢滑过去
  窗3:     [o o o o e e]
  ...
         ↓ 每窗做 FFT
  窗1的频谱: 低频强，高频弱
  窗2的频谱: 开始出现 "o" 的特征
  窗3的频谱: ...
```

### 三个参数决定一切

| 参数 | 典型值 | 权衡 |
|------|--------|------|
| **窗长** (window length) | 20 ms | 越长→频率分辨率高，时间分辨率低 |
| **帧移** (hop length / frame shift) | 10 ms | 越小→时间更精细，但计算量翻倍 |
| **窗函数** (window function) | Vorbis / Hann | 减少"频谱泄漏"，保证完美重建 |

> [!tip] 直觉
> 窗长和帧移的选择就像"照片分辨率 vs 视频帧率"：
> - 窗长大了 → 每张照片很清晰（频率准），但场景变化拍不到（时间不准）
> - 帧移小了 → 视频很流畅（时间准），但每帧模糊（频率不准）
> - 20ms 窗 + 10ms 帧移 是语音处理的黄金标准

## 窗函数为什么重要？

不加窗直接切 → 边缘突变 → FFT 会认为有一个"瞬间跳变" → 产生虚假的高频分量（频谱泄漏）

加窗 → 边缘慢慢衰减到零 → 平滑过渡 → 频谱干净

RNNoise 用 Vorbis 窗：
$$w(n) = \sin\left[\frac{\pi}{2}\sin^2\left(\frac{\pi n}{N}\right)\right]$$

这个窗有一个关键性质：**满足 Princen-Bradley 准则** → 50% 重叠时可以完美重建（把处理后的频谱变回波形时，不会出现音量起伏或相位畸变）。

## 在语音增强中的完整流水线

```
            STFT                          iSTFT
时域 ─────────────────→ 时频域 ─────────────────→ 时域
波形                     频谱图                    波形
(1维数组)               (2维矩阵)                 (1维数组)
                           │
                    在这里做降噪处理
                    (修改频谱的幅度)
```

# 伪代码理解
# 分析（变到频谱图）
for frame in audio.split(20ms, hop=10ms):
    windowed = frame * vorbis_window
    spectrum[frame] = FFT(windowed)  # 复数：幅度 + 相位

# 处理（在这里降噪）
spectrum.magnitude *= estimated_gain   # 只改幅度
# spectrum.phase 保持不变              # 相位原样保留

# 合成（变回波形）

## 频谱图的样子

一个人类在 1 秒内说"hello"的频谱图：

```
频率 (Hz)
4000│ ░░██░░░░░░░░██░░░░█░░░
3000│ ░███░░░░░██░███░██░░░
2000│ ████░░░████░███████░░░
1000│ ████████████████████░░
   0│ ██████████████████████
     ├─────────────────────┤
     0                    1.0  时间 (秒)
     
     █ = 能量高（响），░ = 能量低（安静）
     
     "h"音在高频有能量，"e"音在中高频，"o"音集中在中低频
```

噪声就是叠加在这些"█"上的灰色斑点——RNNoise 的工作是擦掉斑点，保留█。

## 要不要改相位？

大多数传统方法（包括 RNNoise）**只改幅度，不改相位**。

原因：
- 相位对失真人耳非常敏感，随便改会让声音变得像"机器人"
- 幅度是影响噪声感知的主要因素
- 简化问题：只需估计一维的增益（0~1），而非二维的复数

但这是妥协。后续方法（如 DCCRN、PHASEN）开始尝试显式处理相位——这是精度 vs 复杂度的永恒权衡。
