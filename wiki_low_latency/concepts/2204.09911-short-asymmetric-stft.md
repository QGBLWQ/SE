# 2204.09911 - 双窗 STFT、短输出窗与未来帧预测

## 简洁定义

**双窗 STFT-iSTFT（dual-window STFT-iSTFT）**把 analysis window 和用于 overlap-add 的 output/synthesis window 解耦：analysis window 可以保持较长，以获得较高频率分辨率；iSTFT 每帧只保留尾部较短的 output window，从而缩短由 OLA 造成的 algorithmic latency。

2204.09911 的默认例子是：

| 符号 | 含义 | 论文值 |
|---|---|---:|
| iWS | input/analysis window size | 16 ms |
| oWS | output window size | 4 ms |
| HS | hop size | 2 ms |
| DFT | input STFT 的 DFT 长度 | 256 points，129 维复数谱 |
| overlap-add | 每帧 iDFT 后保留的部分 | 最后 4 ms，前 12 ms 丢弃 |

它不是“默认严格因果 STFT”：论文的 16 ms 输入窗对要输出的尾段看前方 4 ms、后方 12 ms，因此应标为 low_look_ahead / frame_online。DNN2 的 one-frame-ahead prediction 可把论文定义的 algorithmic latency 从 4 ms 降到 2 ms，但这是预测未来目标帧，不是严格 sample-causal 的未来观测处理。

## 直觉

普通 STFT-iSTFT 常用同样长的 analysis 和 synthesis window。为了对一个输出样本完成 OLA，系统可能要等到后续重叠帧的预测完成，于是长窗的频率分辨率换来了长 algorithmic latency。

双窗做的事情是：

~~~text
长 analysis window
    -> 频率分辨率较高的 STFT
    -> 复数 DNN / 频域 beamforming
    -> iDFT 得到较长候选帧
    -> 丢弃候选帧前部
短 output window
    -> synthesis window + overlap-add
~~~

在论文的 16/4/2 ms 配置中，DNN 仍然看到 16 ms 的复数频谱，但每帧播放路径只消费最后 4 ms；相邻帧以 2 ms hop 重叠。论文第 2 页 Fig. 1-2 是该时序的直接视觉证据。

## 关键公式

### 分析窗与合成窗

设 analysis window 为 $g$，长度为 $N$；runtime output window 的样本数为 $A$，hop 的样本数为 $B$，且 $A$ 是 $B$ 的整数倍。论文依据 perfect-reconstruction 设计给出：

$$
l[n]=\frac{g[N-A+n]}
{\displaystyle\sum_{k=0}^{A/B-1}
g[N-A+(n\bmod B)+kB]^2},
\qquad 0\le n<A. \tag{16}
$$

- $g[n]$：analysis window；
- $l[n]$：用于保留尾部 output window 的 synthesis window；
- $N$：analysis window 长度；
- $A$：output window 长度；
- $B$：hop 长度；
- 分母：重叠位置上的平方窗归一化，目标是 OLA 后 perfect reconstruction。

论文比较了 square-root Hann、Rect、AsqrtHann 和 Tukey 等 analysis window。AsqrtHann 是一种窗形，不是双窗机制本身。论文构造的 16 ms AsqrtHann 是 30 ms square-root Hann 的前半段与 2 ms square-root Hann 的后半段拼接。

Tukey 窗在论文中定义为：

$$
g[n]=
\begin{cases}
0.5-0.5\cos\left(\dfrac{\pi n}{\alpha N}\right),&0\le n\le\alpha N,\\
g[N-n],&N-\alpha N\le n<N,\\
1,&\mathrm{otherwise},
\end{cases}
\qquad 0\le n<N. \tag{15}
$$

实验对 16 ms Tukey 取 $\alpha=1/16$，也就是左右两端各 1 ms taper。

### 算法时延账本

论文把总 processing latency 分成：

$$
\text{processing latency}
=\text{algorithmic latency}+\text{hardware latency}.
$$

在默认双窗配置：

- current-frame prediction：algorithmic latency 为 4 ms；
- one-frame-ahead prediction：algorithmic latency 为 2 ms；
- two-frame-ahead prediction：论文记账为 0 ms；
- three-frame-ahead prediction：论文记账为 -2 ms。

这些是论文的 algorithmic-latency 定义，不是端到端 capture-to-playback 测量。论文只假设每帧能在 hop time 内完成，未报告硬件 latency、RTF、p50/p95/p99、deadline miss、I/O buffer、ADC/DAC 或 underrun/overrun。

## Future-frame prediction

future-frame prediction 是在不缩短 analysis window 的情况下进一步减少算法账面时延：

1. frame $t$ 读取到的输入用于预测 target frame $t+1$；
2. 下一帧的预测结果可以在当前帧完成 feed-forward 后参与尾部 OLA；
3. 对 16 ms iWS、4 ms oWS、2 ms HS，one-frame-ahead 把 4 ms 降到 2 ms；
4. 继续预测两帧或三帧会迫使网络真正生成更多未来信号，尤其是未来相位，性能明显下降；
5. 双 DNN 系统中 DNN1 保持预测当前 frame，只有 DNN2 采用 future-frame prediction。

论文还发现：current-frame prediction 下四种窗形差异不大，Tukey 略好；one-frame-ahead 时 Rect 通常优于右端 taper 较强的 Tukey 或 square-root Hann，因为 taper 会削弱预测所需的子帧边界信息并造成 artifact。

## 与短分析窗的区别

论文还做了 iWS=oWS=4 ms 的对照：

- zero padding：4 ms window pad 到 16 ms，再用 256-point DFT、129 维复数谱；
- no zero padding：直接用 64-point DFT、33 维复数谱；
- 这两种对照仍可保留 4 ms algorithmic latency，但频率分辨率和网络输入通道改变；
- 六麦 DNN1+MCWF+DNN2、Rect、current-frame 的表中结果分别是 16 ms iWS 的 7.8/2.68/83.6、4 ms iWS 的 7.3/2.58/82.3、4 ms iWS no padding 的 7.4/2.59/82.2（SI-SDR dB / PESQ / eSTOI %）。

这说明本文的重点不是“所有低延迟都要用短 analysis window”，而是把 frequency-resolution budget 与 output-latency budget 分开调节。

## 因果性与复现检查表

| 检查项 | 论文证据 | 复现时必须确认 |
|---|---|---|
| 输入窗未来依赖 | 16 ms 输入窗对目标尾段 look ahead 4 ms | 最后可读输入样本、帧索引和 buffer 对齐 |
| OLA 尾段 | 前 12 ms 丢弃，只用最后 4 ms | 首帧、末帧、边界和 synthesis-window 归一化 |
| 网络时间卷积 | 1x3/1x4 下采样卷积，causal 2x3 residual conv | 每层 padding、缓存状态和是否存在右侧 padding |
| normalization | causal layer normalization；其他 normalization 层被称为 causal/frame-online | 统计量是否只使用允许的帧和历史 |
| LSTM | 3 层，每层 300 units；系统按 frame-online 工作 | state reset、warm-up、长流 state 漂移 |
| MCWF | 统计递推、t=0 全零、Woodbury 逆更新 | 递推状态、数值正则化、源移动时更新策略 |
| 首帧初始化 | 每个 mixture 开头补 $(iWS-HS)$ ms 零样本；MCWF 统计在 $t=0$ 全零 | DNN 状态 reset 与流式 warm-up 过程 |
| future prediction | DNN2 可预测一帧或更远 future frame | 预测帧与输出帧的时间对齐、边界 artifact、phase 误差 |
| hardware / deadline | 只假设每帧能在 hop 内完成；未报告目标硬件上的 RTF 或 deadline miss | 目标 CPU/SoC、batch=1、RTF、p99、underrun/overrun 和 capture-to-playback |
