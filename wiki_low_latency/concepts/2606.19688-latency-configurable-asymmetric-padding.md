# 2606.19688 - 非对称时间 padding 作为时延旋钮与选择性状态更新

## 定义

**非对称时间 padding 作为时延旋钮**（asymmetric temporal padding as a latency knob）指的是：不改卷积核大小、不改参数量、不改架构拓扑，只把每一层在时间轴上「可用的 padding 预算」在左侧（过去）与右侧（未来）之间重新分配，从而让同一个骨干在训练期被配置成不同的算法时延点。

它必须和另外两个机制一起使用才成立：

1. **dual-buffer streaming**：state buffer 保存过去激活、lookahead buffer 在输入级与特征级提供未来帧；
2. **selective state update (SSU)**：用一个选择算子把状态写入范围限制在「当前 chunk 帧」，防止 lookahead 帧被写进 state 后在下一个 chunk 里被重复回放。

这三者共同保证 **chunk-wise 推理与 full-sequence 推理在数值上等价**。反过来说：**没有 SSU，非对称 padding 在流式场景下是不可用的**——这一点被论文的消融实验量化了（见下文）。

## 直觉：为什么「重分配 padding」等于「配置时延」

一个时间轴卷积核大小 $K$、左右 padding 为 $(P_L,P_R)$ 时，输出位置 $t$ 读取的输入范围是

$$
[t-P_L,\ t-P_L+K-1]=[t-P_L,\ t+P_R],
$$

前提是 $P_L+P_R=K-1$（即标准 "same" padding 的约束，论文写作 $P_{\text{tot}}=2P$）。于是：

- **过去访问量** = $P_L+1$ 个时间点；
- **未来访问量** = $P_R$ 个时间点，也就是这一层对算法时延的贡献；
- **感受野大小** = $K$，与 $P_L,P_R$ 的分配**无关**。

所以「对称 padding」只是 $P_L=P_R=P$ 这一特例；把它改成 $r_R<0.5$ 就等于**用未来上下文换过去上下文**，而计算图和参数量原封不动。

## 公式推导

### ① padding 分配式

$$
P_L=\operatorname{round}(P_{\text{tot}}\cdot r_L),\qquad P_R=P_{\text{tot}}-P_L,\qquad r_L+r_R=1,\qquad P_{\text{tot}}=2P.
$$

- $P_{\text{tot}}$：一层卷积在时间轴上的总 padding 预算，由 kernel 决定，**训练与推理全程固定**；
- $r=(r_L,r_R)$：所有非对称卷积层**共享**的固定训练期超参数，不随 SNR、输入内容或运行条件变化；
- $P_R>0$ 即引入未来帧访问。频率轴 padding 保持对称，只有时间轴被切分。

因为 $P_{\text{tot}}$ 固定，论文的三个「不变」成立：感受野不变、参数量不变、架构不变。变的只有「过去/未来访问比」。

### ② 时延累加：串行求和、并行取最大

$$
L_{\text{enc}}=\sum_{\ell\in E}P_R^{(\ell)},\qquad
L_{\text{dec}}=\max_{b\in\mathcal B}\sum_{\ell\in D_b}P_R^{(\ell)},\qquad
\mathcal B=\{\text{mask},\text{phase}\},
$$

$$
\tau_{\text{ms}}=1000\cdot\frac{(L_{\text{enc}}+L_{\text{dec}})\cdot h+W/2}{f_s}.
$$

- $E$：encoder 中的非对称卷积层；$D_b$：decoder 分支 $b$ 中的同类层；
- 串联层之间 lookahead **累加**（第 2 层看未来的第 1 层输出，等于更远的未来输入）；
- mask 与 phase 解码器**并行**，所以它们的 lookahead 取 $\max$ 而不是求和；
- $(L_{\text{enc}}+L_{\text{dec}})\cdot h$：把 lookahead 帧数换成样本数——**一帧 lookahead 只花一个 hop**，不是一整个 window；
- $W/2$：STFT center delay。**这一项与 $r$ 无关**，是整套机制无法触及的下界。

> [!note] 由 ② 直接推出的两个结论（本页推导，论文未逐条写出）
> **（a）时延阶梯的粒度 = hop。** 令 $L_{\text{tot}}=L_{\text{enc}}+L_{\text{dec}}$，则
> $$\tau=1000\cdot\frac{W/2}{f_s}+L_{\text{tot}}\cdot\frac{1000\,h}{f_s}=\underbrace{12.5}_{\text{不可调}}+\underbrace{6.25\,L_{\text{tot}}}_{\text{可调}}\ \text{ms}.$$
> 所以「可配置」是**量化**的：最小步长 6.25 ms（16 kHz、hop=100）。要更细的粒度必须减小 hop。
>
> **（b）decoder 的 max 记账留出了"免费"的时延空间。** 因为 $L_{\text{dec}}$ 取两条分支的最大值，只要不超过另一条分支，**单独给 mask 或 phase 解码器增加 lookahead 不增加总时延**。这是一个未被论文利用的结构性余量：可以用非对称的 decoder 配置（例如相位分支多给几帧、掩蔽分支保持因果）去换质量而不付时延。

### ③ state buffer：把零左填充换成真实过去

$$
\tilde x_k^{(\ell)}=\big[\,s_{k-1}^{(\ell)};\ x_k^{(\ell)};\ \mathbf 0\,\big],\qquad
s_k^{(\ell)}\leftarrow\text{last }P_L^{(\ell)}\text{ frames of }x_k^{(\ell)}.
$$

$s_{k-1}^{(\ell)}$ 是上一 chunk 结束时本层保存的最近 $P_L^{(\ell)}$ 帧真实激活，$\mathbf 0$ 是右侧零填充，$\tilde x_k^{(\ell)}$ 是拼好后喂给卷积的输入。若不做这一步，chunk 边界处填零会与 full-sequence 处理不一致（这正是 FastWaveNet / cached convolution / Denoiser 一路的做法）。

### ④ lookahead buffer：把未来帧真的取进来

- **输入级（encoder）**：当 $L_{\text{enc}}>0$，encoder 输入从 $C$ 帧扩展到 $C+L_{\text{enc}}$ 帧，使每个 encoder 卷积访问真实未来帧；
- **特征级（decoder）**：当 $L_{\text{dec}}>0$，encoder 输出累积进 feature buffer，**只有 `buffered frames ≥ C+L_dec` 时才调用 decoder**；decoder 拿到扩展特征序列，但**只输出当前 chunk 对应的部分**，其余帧纯作上下文。

因为「被输出区域」与「零右填充边界」之间至少隔着 $L_{\text{dec}}$ 帧，所有输出都建立在真实未来上下文之上。

### ⑤ 选择性状态更新：本机制的关键补丁

**问题。** 设 chunk size 为 $C$、累计 lookahead 为 $L$。chunk $k$ 的扩展输入覆盖帧区间 $[kC,\ kC+C+L)$。如果状态更新直接用整个扩展输入：

$$
s_k^{(\ell)}\leftarrow\text{last }P_L^{(\ell)}\text{ frames of }x_{k,\text{ext}}^{(\ell)},
$$

那么当 $P_L^{(\ell)}>0$ 且扩展窗口越过 $kC+C$ 时，被写入 state 的帧**有一部分落在 lookahead 区域**。这些帧在 chunk $k+1$ 会作为新到达的当前帧**再出现一次**——一次来自 state（当作"过去"），一次来自新输入（当作"现在"）。卷积因此看到一段被复制的时间片段，输出被扭曲，而且**每个 chunk 都会再叠一层**，随 chunk 数累积。

**修复。** 引入选择算子

$$
\Pi_C(x)=x_{1:C},
$$

它只保留当前 chunk 的帧，于是

$$
s_k^{(\ell)}\leftarrow\text{last }P_L^{(\ell)}\text{ frames of }\Pi_C\big(x_{k,\text{ext}}^{(\ell)}\big).
$$

**lookahead 帧参与前向计算，但永不写入 state。**

**为什么污染随 lookahead 单调增长。** 被错误写入 state 的帧数随「扩展窗口越过当前 chunk 边界的长度」增长，而该长度正是 $L$。所以：

- $L_{\text{tot}}=0$ 时扩展窗口不越过边界，SSU 是**完全的 no-op**（消融中 $\Delta=0.00$ 精确吻合）；
- $L_{\text{tot}}$ 越大，被复制的片段越长，退化越严重（消融中 $-1.56\to-2.00\to-2.09$ 单调恶化）；
- 对称 padding（$r_R=0.5$）下左右等分使 $P_L$ 相对减小、state buffer 变短，被复制的片段随之变短，退化更轻（消融中 $-1.48$）。

这条推理链让 Table 2 的消融不只是「掉点」，而是**可被机制预测的定量模式**。

### ⑥ 等价性成立的条件（本页归纳）

要让 chunk-wise 输出**逐样本等于** full-sequence 输出，必须同时满足：

| 条件 | 对应机制 | 不满足时的症状 |
|---|---|---|
| 每层左 padding 用真实过去激活填充 | state buffer（③） | chunk 边界 artifact，边界处与离线不一致 |
| 每层右 padding 用真实未来帧填充 | lookahead buffer（④，输入级 + 特征级） | 输出用零代替未来，等价性只在 $r_R=0$ 时成立 |
| 状态只记录当前 chunk 帧 | SSU（⑤） | lookahead 帧被重复回放，误差随 chunk 累积 |
| 归一化统计与序列长度无关 | InstanceNorm → BatchNorm | 不同 chunk size 下统计量不同，结果随分块方式漂移 |
| 注意力/池化不跨时间做全局聚合 | AdaptiveAvgPool1d → CausalConv1d | 隐式未来泄漏，等价性直接破裂 |

最后两行是本篇的**工程侧必要条件**，也是最容易在复现时漏掉的两点——论文明确指出 global pooling「aggregates future frames, violating causality」。

## 时延账本与迁移边界

| 项目 | 论文证据 | 本 Wiki 判定 |
|---|---|---|
| STFT window / hop | 400 / 100 samples @16 kHz = 25.0 / 6.25 ms | `low_look_ahead`：Eq. (3) 计入 $W/2=12.5$ ms center delay，前端本身需要 12.5 ms 未来样本 |
| padding 分配 | $P_L=\operatorname{round}(P_{\text{tot}}r_L)$、$P_R=P_{\text{tot}}-P_L$ | $r_R=0$ → `strict_causal`；$r_R>0$ → `low_look_ahead`，上界 $L_{\text{enc}}+L_{\text{dec}}$ 帧 |
| 时间轴卷积 | TS Block time branch 全因果（Figure 1(a) 标注 "Time Stage (Causal)"） | `strict_causal`（论文声明 + 结构证据，无逐层 certificate） |
| 频率轴卷积 | freq branch 非因果（"Freq Stage (Non-Causal)"） | 只访问当前帧 → 时间维度仍 `strict_causal` |
| 归一化 / 池化 | InstanceNorm→BatchNorm；AdaptiveAvgPool1d→CausalConv1d | `strict_causal`（论文识别并修掉的显式未来泄漏点） |
| 状态 | state buffer + feature buffer + SSU | 设计上 `strict_causal`；warm-up / reset / 长流漂移未报告 |
| 计算 | 单线程 Xeon Silver 4510，ONNX Runtime；RTF 4.59@$C=1$ → 0.30@$C=64$；RTF<1 需 $C\ge7\text{–}12$；$C=8$ 因果 62.5 ms / RTF 0.77 | 吞吐证据；$C=1$ 不实时，实时工作点总时延升至 ~56–88 ms |
| 端到端 | 只到 algorithmic + chunk buffering | ADC/DMA、I/O、DAC、capture-to-playback、underrun/overrun **未验证** |

**可迁移的部分：**

- 「padding 重分配 = 时延旋钮」可以搬到任何使用因果卷积 + 显式 lookahead 的流式前端；**前提是该前端已经解决了 $W/2$ 型固定下界**，否则旋钮只能在一个远高于 2 ms 的基线上摆动。要做 2 ms 级系统，必须先换短窗/非对称窗前端（见 [[wiki_low_latency/concepts/2204.09911-short-asymmetric-stft]]）。
- **SSU 是一条通用设计规则**：任何"既缓存过去状态、又显式缓冲未来帧"的系统都必须检查「被写入 state 的帧是否会在后续 chunk 中重复出现」。本库中所有做 lookahead 的因果模型都值得用这条规则体检。
- 归一化与池化的因果体检清单（InstanceNorm→BatchNorm、global pooling→causal conv）可以直接复用到其他论文的复现审查。

**不可迁移的部分：**

- $r$ 是固定的训练期超参数，**不能运行时切换**。要真正"按场景调时延"，需要训练期就覆盖多档（或多模型切换），而论文每个时延点独立训练 400K steps × 3 seeds，成本并未报告。
- 论文没有给出任何目标硬件、量化、内存或功耗数据，因此不能据此推断端侧可行性。

## 与库中其他概念页的关系

- **同为「非对称」，但作用轴不同**：[[wiki_low_latency/concepts/2204.09911-short-asymmetric-stft]] 把 analysis window 与 synthesis window 解耦（长窗取频率分辨率、短窗取低时延），本篇把 conv padding 在左右之间重新分配。一个是**前端窗级**的非对称，一个是**网络层级**的非对称；两者正交，可以叠加。
- **被明确对照的既有约束**：[[wiki_low_latency/entities/DeepFilterNet2]] 的 lookahead 只从全局输入平移进入、每个卷积保持纯因果；cached convolution 把对称 padding 等价成固定输出延迟。二者都「deliberately preclude per-layer asymmetric padding」，本篇的贡献就是解除这个限制并付出 SSU 的代价。
- **延迟账本口径**：[[wiki_low_latency/concepts/低时延前端与延迟账本]]、[[wiki_low_latency/concepts/严格因果与算法延迟]]、[[wiki_low_latency/concepts/2409.10358-ultra-low-latency-benchmark]]。本篇提供了目前库内最可复算的一份 Eq. (3) 口径，适合作为基准把其他论文的时延重新记账。
- **因果时域对照**：[[wiki_low_latency/concepts/2103.14882-causal-tasnet]] 的因果 learned-filterbank 路线是另一种"把因果性做成结构约束"的方式。
- **缺失维度**：[[wiki_low_latency/concepts/低 SNR 人声保留评估]] 提供了本篇完全空缺的验收字段。

> [!question] 当前缺口
> 这套机制证明了「同一架构内时延可配置」在 12.5–200 ms 区间成立，但没有证明它可以下沉到 2 ms：$W/2$ 是不可调的下界，且实时工作点（$C\ge7\text{–}12$）会把总时延推回 62.5 ms 量级。
> 另外，论文声称的 chunk-wise/full-sequence 数值等价是断言而非可独立验证的证据；Table 1（3.35）与 Table 2（3.39）在同一配置上的 PESQ 差异也未被论文对齐说明。
