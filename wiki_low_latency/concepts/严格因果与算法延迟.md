# 严格因果与算法延迟

## 定义

严格因果（strict causal）要求输出在时刻 $t$ 只依赖当前或过去已观测样本，不读取未来 waveform、future STFT frame 或隐式 center padding。算法延迟只描述前端窗口、hop、look-ahead、OLA 等信号处理等待，不等同于模型计算时间或 capture-to-playback。

## 延迟账本

| 字段 | 要记录什么 |
|---|---|
| window / hop | 前端需要收集多少样本、多久更新一次 |
| look-ahead | 显式 future frame、对称窗、center padding、DF taps |
| model compute | batch=1 的 p50/p95/p99 和峰值 MAC/SRAM |
| I/O | ADC/DMA、driver buffer、线程调度、DAC/playout |
| deadline | 每个 hop 的 miss/underrun 数与 worst-case margin |
| state | warm-up、reset、flush、丢帧/抖动时的状态策略 |

## 本库判定规则

- 论文只写 causal，不给逐层 receptive field、padding、状态和设备测量时，标为论文级 causal，不标为已认证 strict_causal。
- RTF<1 或平均 MAC/s 只能证明平均吞吐，不能替代目标硬件 p99 deadline。
- 2 ms、4 ms 等算法前端数字不能自动覆盖 capture-to-playback。
