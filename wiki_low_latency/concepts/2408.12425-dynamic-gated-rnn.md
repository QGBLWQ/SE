# 2408.12425 - 神经元级动态计算与固定比例稀疏

## 定义

**神经元级动态计算**（neuron-level dynamic computation）指的是：在循环网络的**每一个时间步内部**，只更新隐状态的一部分**分量**，其余分量保持上一步的值。它跳的对象是**神经元**，不是时间步——因此 $h_t$ 在每一步都存在、并被完整地传给 $t+1$，只是其中一部分分量等于 $h_{t-1}$ 的对应分量。

**固定比例稀疏**（fixed-ratio sparsity）是这套机制的一个关键设计选择：每一步要更新的神经元数量是**预先设定的常数** $A=(P/100)\cdot J$，而不是由数据决定的变量。这个选择由 [[wiki_low_latency/sources/2024/D-GRU 2024]]（下称 D-GRU 论文）提出，其论证是：

> 只要每步的更新量不固定，硬件就必须按"全部神经元都更新"的最坏情况预留能力，省下来的算力在实时约束（deadline）上兑现不了。

因此本页的核心命题是：**"跳多少"这件事，其可预测性比其平均值更重要。**

## 直觉：两种"跳过"的粒度差

两条路线都叫"跳过更新"，但跳的对象不同，后果也完全不同。

~~~text
【A】时间步级跳过（Skip RNN，引文 [29][30][31]）
     门是标量：g_t ∈ {0, 1}                      ← 整层共用一个门
     s_t = g_t · s̃_t + (1 − g_t) · s_{t−1}
       g_t = 1 → 全层 J 个神经元一起更新
       g_t = 0 → 全层 J 个神经元一起停更，输出 == 上一步输出
     每步更新数量 n_t ∈ {0, J}                  ← 两步跳变，最坏情况 = J
     串行宿主里 mask 会"冻结" → 音频伪影（引文 [20] TinyLSTM 的失败先例）

【B】神经元级跳过（D-GRU，本篇）
     门是长度 J 的向量：g_t ∈ {0,1}^J           ← 每个神经元一个门
     每步恰好 A = (P/100)·J 个 1（取 z_t 的 top-A）
     h^j_t = z^j_t·c^j_t + (1−z^j_t)·h^j_{t−1}   if g^j_t = 1
     h^j_t = h^j_{t−1}                            if g^j_t = 0
     每步更新数量 n_t ≡ A                        ← 恒为常数
     h_t 始终存在并向后传递，输出从不"冻结"
~~~

两条推论：

1. **A 路线需要"并行宿主"才能用；B 路线不需要。** 因为 A 路线在 $g_t=0$ 时整层输出等于上一步，若该层是唯一决定 mask 的通路，mask 就停更了（[[wiki_low_latency/entities/Skip-DPCRN]] 的页面把这条写成引用时的必备前提）。B 路线每步都有 $A$ 个分量被刷新，输出持续变化，因此**可以直接作用在串行的 `FC → GRU → GRU → FC` 骨干上**——这正是 D-GRU 论文 Table 1 里那个 1.34 M 骨干的形态。
2. **A 路线的漂移是"整层停更 N 步"；B 路线的漂移是"部分分量长期陈旧"。** 后者不会造成台阶状伪影，但如果某个神经元的 $z^j_t$ 长期偏低，它可能长期进不了 top-A。论文承认这会「introducing internal noise」，但**没有量化**（见下文「证据中的收益」与「迁移边界」）。

## 机制公式

### ① 通用 DG-RNN：select gate 与隐状态

$$
g_t = \mathcal{B}\big(\mathcal{G}(x_t,\ h_{t-1})\big),\qquad
h^j_t =
\begin{cases}
F^j(x_t,\ h_{t-1}), & g^j_t = 1,\\
h^j_{t-1}, & g^j_t = 0.
\end{cases}
$$

- $\mathcal{G}(\cdot)$：算出 select gate 的网络；$\mathcal{B}(\cdot)$：二值化；
- $g_t\in\{0,1\}^J$：长度 $J$ 的二值向量，$J$ 是神经元总数；
- 每步的更新百分比 $P_t=\big(\sum_{j=1}^{J} g^j_t\big)/J\times 100$。

### ② D-GRU：用 $z_t$ 直接导出 select gate（零额外参数）

$$
g^j_t =
\begin{cases}
1 & \text{if } z^j_t \text{ is among the top-}A\text{ largest elements of } z_t,\\
0 & \text{otherwise},
\end{cases}
\qquad
A = \frac{P}{100}\times J .
$$

**为什么可以拿 $z_t$ 当重要性分数。** 由 GRU 的隐状态式

$$
h_t = z_t * c_t + (1 - z_t) * h_{t-1},
$$

可知 $h_t$ 是 $h_{t-1}$ 与候选态 $c_t$ 的**逐元素加权平均**，权重正是 $z_t$：$z^j_t\to1$ 表示该神经元本步被 $c^j_t$ 大幅替换（**变化大**），$z^j_t\to0$ 表示 $h^j_t\approx h^j_{t-1}$（**几乎没变**）。所以

$$
\text{「取 } z_t \text{ 的 top-}A\text{」}\ \equiv\ \text{「跳过本步变化最小的 } J-A \text{ 个神经元」}
$$

而 $z_t$ **本来就要算**（它既要用于 $h_t$ 的合成，又要用于选择），所以 select gate **不引入任何额外权重**——这正是 D-GRU 相对通用 DG-RNN 的化简。论文对 select gate 另加了一条轻量化约束：「the select gate generation process should be lightweight to not negate the advantages of sparse update.」

### ③ 被跳过的计算

$$
r^j_t =
\begin{cases}
\sigma\big(w^j_{ir}x_t + b^j_{ir} + w^j_{hr}h_{t-1} + b^j_{hr}\big) & g^j_t = 1,\\
\text{(skipped)} & g^j_t = 0,
\end{cases}
\qquad
c^j_t =
\begin{cases}
\tanh\big(w^j_{ic}x_t + b^j_{ic} + r^j_t * (w^j_{hc}h_{t-1} + b^j_{hc})\big) & g^j_t = 1,\\
\text{(skipped)} & g^j_t = 0.
\end{cases}
$$

注意 $h_{t-1}$ 仍是**完整向量**（全部 $J$ 个分量都作为矩阵乘的输入），被裁剪的是**输出行数**（只算 $A$ 行）。这就是"$P\%$ 的计算量"的确切含义，也是后文"访问模式不规则"这一隐患的根源。

### ④ 成本公式与它的**结构性下限**

| 分量 | 常规 GRU | D-GRU | 能否省 |
|---|---:|---:|---|
| reset gate $r_t$ | 1 单位 | $P/100$ | 能省 |
| update gate $z_t$ | 1 单位 | **1 单位** | **不能省**（top-A 选择需要完整 $z_t$） |
| candidate $c_t$ | 1 单位 | $P/100$ | 能省 |
| **合计** | **3 单位** | $1+2P/100$ | —— |

$$
\frac{\text{cost(D-GRU)}}{\text{cost(GRU)}} = \frac{1 + 2P/100}{3}
\ \xrightarrow[\ P\to 0\ ]{}\ \frac{1}{3}.
$$

**这个公式有一个容易被忽略的推论：D-GRU 的算力节省存在硬上限 $2/3$。** 因为 $z_t$ 无论如何都要全量计算，即使把 $P$ 压到 0，GRU 层仍要付出 $1/3$ 的算力。把它换算到整个模型（按 Table 1 的 non-GRU / GRU 分项，本页推导）：

| 骨干 | GRU 层算力占比 | GRU 层的算力下限 | **整个模型的算力下限** | $P=25$ 实测 | $P=50$ 实测 |
|---|---:|---:|---:|---:|---:|
| GRU | 92.4% | $1/3$ | **38.4%** | 53% | 69% |
| MPT | 74.6% | $1/3$ | **50.2%** | 62% | 75% |
| DPRNN | 85.7% | $1/3$ | **42.8%** | 57% | 71% |

也就是说：**即便把神经元更新数压到零，GRU 骨干也永远降不到基线算力的 38% 以下。** 这给"继续降 $P$"这条路线划了一条明确的死线——而 $P=25$ 时质量已经开始显著退化（见下），说明**实际可用区间比理论区间窄得多**。

## 为什么固定比例能保证每步算力恒定

把"每步的更新数量"记作 $n_t$，每步算力记作

$$
c_t = C_{\text{ng}} + C_{\text{g}}\cdot\phi(n_t),
$$

其中 $C_{\text{ng}}$ 是非 GRU 层的固定成本，$C_{\text{g}}$ 是 GRU 层全量成本，$\phi$ 是把更新数量映射成成本比例的单调函数（对 D-GRU 而言 $\phi(n)=(1+2n/J)/3$）。那么：

| 方法 | $n_t$ 的取值范围 | $\max_t c_t$ | 是否降低了**最坏情况**算力 |
|---|---|---|---|
| Skip RNN [29, 30, 31] | $\{0,\ J\}$ | $C_{\text{ng}}+C_{\text{g}}$ | **否**（= 基线） |
| Phased LSTM [28] | 随相位变化 | $C_{\text{ng}}+C_{\text{g}}$ | **否**（= 基线） |
| Delta RNNs [18, 26, 27] | 随输入变化 | $C_{\text{ng}}+C_{\text{g}}$ | **否**（= 基线） |
| **D-GRU**（top-$A$） | $\{A\}$（单点） | $C_{\text{ng}}+C_{\text{g}}\phi(A)$ | **是**（$<$ 基线） |

**结论：只有让 $n_t$ 的取值范围塌缩成一个点，才能降低最坏情况算力。** 这正是"固定比例"的全部意义——它不是为了让平均更省（平均节省由 $P$ 决定，与"固定还是浮动"无关），而是为了让**峰值等于平均**。

## 为什么这对硬件实时约束是决定性的

实时音频链路有**每个 hop 的 deadline**。设 hop 为 $T_{\text{hop}}$，则系统必须满足

$$
\max_t c_t \ \le\ \text{budget}(T_{\text{hop}}).
$$

- **时间步级跳过**：$\max_t c_t = C_{\text{ng}}+C_{\text{g}}$，与基线**完全相同**。约束没有放松 → **平均节省只兑现为平均功耗/发热，兑现不了 deadline 余量**。硬件仍须按基线规模选型。这是 [[wiki_low_latency/concepts/2207.11108-inference-skipping-parallel-rnn]] §⑤ 那条 [!note] 的核心，也是 Skip-DPCRN 的"平均省 33%、峰值只降约 15%"所暴露的问题。
- **D-GRU（固定比例）**：$\max_t c_t = C_{\text{ng}}+C_{\text{g}}\phi(A)$，约束被**确定地**放松了 $\phi(A)$ 倍 → **可以用更慢/更便宜/更小的器件，或把腾出的余量花在更大的模型上**。

> [!note] 两条路线是同一枚硬币的两面，本库应成对阅读
> - [[wiki_low_latency/sources/2022/Skip-DPCRN 2022]]：**接受**算力随输入波动，用"平均省 32.8%"论证价值 → 其页面自己指出这省下的是**平均功耗/发热**，不是最坏情况 deadline。
> - D-GRU（本篇）：**拒绝**波动，用"每步算力恒定"论证价值 → 它把上面那个缺口**在设计层面堵上了**。
> 两者对同一现象给出了相反评价，而**两者都对**——分歧点在于**是否要求逐帧可预测的算力**。D-GRU 的整篇立论（包括它否掉阈值型 select gate 的理由）都建立在这一条上。

> [!warning] 但"算力恒定" ≠ "墙钟时间恒定"——这是本篇最大的未验证环节
> D-GRU 保证的是 **MAC 计数恒定**，不是**执行时间恒定**。top-$A$ 选择是一个**数据相关**的算子：
> - 每步被选中的**行下标集合 $\mathcal S_t$ 都在变**，因此矩阵乘的**访问模式是不规则的**（gather/scatter、无法向量化的行选择、掩码或分支开销）；
> - 在选择算子本身的开销上，论文只论证了 $O(J)$ 的**选择复杂度**（引 [19]，线性时间选择）"可忽略"，**没有论证**它在真实硬件上的常数因子；
> - 论文批评阈值法时说"硬件仍须按最坏情况预留全部算力"——**这个批评对称地适用于它自己的方案**：若硬件不能高效地做 $A$ 行矩阵乘，那么"恒定算力"在墙钟时间上也兑现不了。
>
> 论文**完全没有测量**这一点：无 RTF、无 per-step wall-clock、无 p99、无目标硬件、无峰值 RAM/SRAM。因此本库把"每步算力恒定"记为**设计保证（MAC 计数层面）**，**不是实测保证**。

## 「平均算力」与「峰值算力」不是一回事

| 口径 | Skip-RNN 类（时间步级跳过） | D-GRU（神经元级固定比例） |
|---|---|---|
| 每步更新数量 $n_t$ | 随步变化（$0$ 或 $J$） | 恒为 $A$ |
| 平均算力 | 低于基线 | 低于基线 |
| **峰值算力（设计）** | ≈ 基线（未降低） | **= 平均值**（按设计降低） |
| 硬件必须预留的能力 | 基线全量 | 降低后的值 |
| 论文报告的**峰值**证据 | Skip-DPCRN：定性说法「峰值算力只降约 15%」（Fig. 6，小提琴图，无分位数） | **未报告** |
| 论文报告的 **p99 / per-step wall-clock** | **未报告** | **未报告** |
| 论文报告的 **平均 MACs** | 测试集平均值（输入相关） | 固定值（输入无关，Table 1 单一数字） |

**本页的判定**：在 **MAC 计数口径**下，D-GRU 的"平均 vs 峰值"落差被设计**消除**了（这正是它相对 Skip-DPCRN 的实质进步）；但在**测量口径**下，两篇**都没有**报告峰值/p99/墙钟时间，因此：

- 「省 33% 平均算力」与「省 33% 峰值算力」在 D-GRU 这里是**同一个数**（因为是常数）——这是它比 Skip-DPCRN 强的地方；
- 但这个"同一个数"**从未被测量验证**，也没有转化为任何延迟或功耗结论。论文只报了 MACs。

> [!question] 未报告项（本篇与 Skip-DPCRN 共同的空白）
> 两篇都**没有**报告：p99 / worst-case wall-clock、deadline miss、峰值 RAM/SRAM、量化/定点、功耗、目标硬件。因此本库**不能**据此推断端侧可行性；"平均算力可预测"到"deadline 有保障"之间，仍隔着一次真实的硬件测量。

## 与 Delta RNN / Phased LSTM / Skip RNN 的对比

论文在 §6 用一段话把三类既有"动态计算"方法与 DG-RNN 划开，本页把它整理成表：

| 方法 | 触发信号（何时跳） | 跳过粒度 | 每步更新数量 | 每步算力 | 最坏情况算力 | 论文对它的定位 |
|---|---|---|---|---|---|---|
| **Delta RNNs** [18, 26, 27] | 输入的跨步变化是否超过阈值 $\theta$ | 神经元级 | **不固定**（输入驱动） | 随步变化 | = 基线 | 「另一条正交的路」，提议未来统一到一个框架 |
| **Phased LSTM** [28] | 振荡周期的特定相位 | 神经元级 | **不固定**（相位驱动） | 随步变化 | = 基线 | 明确批评：更新数随步变化 → 算力动态变化 |
| **Skip RNN** [29, 30, 31] | 学习到的累积概率 $\tilde p_t$ | **整步（全部神经元）** | $0$ 或 $J$ | 随步跳变 | = 基线 | 明确批评：算力随步变化；且**主要在分类任务上验证**，回归任务（如语音增强）上的表现尚待研究 |
| **D-GRU**（本篇） | $z_t$ 的 top-$A$ | 神经元级 | **恒为 $A=(P/100)\cdot J$** | **恒定** | **$<$ 基线**（设计值） | —— |

三点值得单独记住：

1. **Delta RNN 是"输入驱动"，D-GRU 是"状态驱动"。** Delta RNN 看的是**输入变化**，D-GRU 看的是**update gate $z_t$**（由输入与历史状态共同决定）。论文认为两者可以统一——这是一个明确的 future work，也是一个可直接做的实验方向。
2. **"神经元级"不等于"算力恒定"。** Delta RNN 与 Phased LSTM 都是神经元级的，但更新数量随数据/相位变化，因此**最坏情况仍等于基线**。真正决定可预测性的是"数量固定"，不是"粒度细"。
3. **Skip RNN 的粒度最粗（整步），所以它连"不需要并行宿主"这一关都过不了**——这是它需要 [[wiki_low_latency/entities/Skip-DPCRN]] 那种 parallel RNN 宿主的结构原因。

| DPRNN（100 起） | 0.622 | 0.358 | **0.042** |

**支持**：$P\ge50\%$ 时三个骨干的 PESQ 差异全部不显著（此时 GRU 层算力省 33.33%，整体算力降到 69%/75%/71%）；参数量跨全部 $P$ 档位不变（零额外参数）；{−5,0,5} dB 上趋势一致。
**不支持**：每步算力恒定性已被**测量**；算力节省已转化为墙钟时间/功耗；长流状态漂移可控；阈值型 select gate 的质量代价已知（从未评估）；低 SNR 人声保留已证明。

> [!note] 退化幅度与"GRU 层承担的建模职责比例"正相关
> 论文把 MPT 在 $P=25$ 处不显著归因于「more non-GRU layers... might compensate for inaccuracies in the D-GRUs, **albeit with a sacrifice of less computation savings**」。本页把它读成一条连续的解释链：
> - GRU 骨干（non-GRU 仅 **7.6%**）→ 省得最多（$P=50$ 降到 69%）→ $P=25$ 最先显著崩（p=0.035）；
> - DPRNN（non-GRU **14.3%**）→ 居中（71%）→ 刚好越过显著线（p=0.042）；
> - MPT（non-GRU **25.4%**）→ 省得最少（75%）→ $P=25$ 仍不显著（p=0.121）。
> 即 **D-GRU 的"省多少"与"崩多早"是同一个结构变量的两面**。这个读法比论文原文更完整，也是本库做跨骨干比较时应采用的框架。

## 时延账本与迁移边界

| 项目 | D-GRU 证据 | 本 Wiki 判定 |
|---|---|---|
| 采样率 / FFT / 帧长 / hop | 16 kHz；320-point FFT；20 ms 帧长；10 ms overlap（⇒ hop 10 ms、50% overlap、100 帧/s） | 明确（频率点数 $F=161$ 为本页推得） |
| STFT 帧锚定 / center | **未报告** | `unreported`：若 center=True 则前端含 $W/2=10$ ms 未来样本 |
| 因果性 | 论文原话「three strong causal speech enhancement models」，**无逐层 certificate** | `paper-claimed-causal` |
| 算法延迟 | **完全未报告**——无 window−hop、无 $W/2$、无推导式 | `unreported` |
| 每步算力 | $P$ 固定 ⇒ MAC 计数恒定（设计保证） | 可预测（MAC 口径）；**未测量** |
| 峰值 / p99 / wall-clock | **全部未报告** | 未验证 |
| 运行时 / 端到端 | RTF、目标硬件、量化、功耗、RAM/SRAM、ADC/DAC、underrun/overrun **全部未报告** | 未验证 |

**可迁移的部分：**

1. **「先看最坏情况，再看平均值」这条审计顺序**可以直接搬到任何"动态算力"方法的评估上：先问 $\max_t c_t$ 是否低于基线，再问 $\mathbb E[c_t]$ 是多少。凡是 $\max_t c_t$ 等于基线的方法，其节省都只能计入**平均功耗**，不能计入 **deadline 余量**。
2. **「用模型自己已有的中间量当门控信号」是一个通用省参数的技巧。** D-GRU 用 $z_t$（本来就要算）当重要性分数，因此零额外参数。任何已有"逐单元重要性"中间量的循环结构（LSTM 的 output gate、SSM 的门控项）都可以套用这个思路。
3. **「固定数量 + 自由选择身份」是"恒定算力 + 自适应"的可行折中。** 数量固定保证算力可预测，身份自由让模型自己决定把预算花在哪——这个组合可以搬到其他条件计算场景（如 token 选择、通道选择）。
4. **成本公式 $(1+2P/100)/3$ 的"不可省项"记账法**（哪些分量无论如何都要算）值得复用：它直接给出了节省的**理论上限**，避免在错误的区间里继续调参。

**不可迁移 / 需要先解决的部分：**

1. **MAC 计数恒定 ≠ 墙钟时间恒定。** 不规则行选择（gather/scatter）的开销未被测量；若目标硬件无法高效做 $A$ 行矩阵乘，节省无法兑现。
2. **没有延迟账本。** 10 ms hop 是否构成算法延迟、是否存在 look-ahead、端到端多少，**全部未报告**——本页**不能**据此判断它与约 2 ms 硬约束的距离。
3. **长流状态漂移未测。** "部分分量长期陈旧"是神经元级稀疏特有的风险，论文只给了定性描述（"introducing internal noise"）。
4. **人声保留维度空白。** 只有 PESQ/ESTOI/SISNR/DNSOVAL（且 **DNSMOS 只报 OVL，无 SIG/BAK**），无 false-suppression / ASR WER / F0 / prosody / voiced energy。

## 与库中其他概念页的关系

- **同问题谱系的反面（必须成对阅读）**：[[wiki_low_latency/concepts/2207.11108-inference-skipping-parallel-rnn]] 把"推理期状态跳过"抽象成可复用概念，并论证 **parallel RNN 是前提、目标率约束是硬件友好的关键**。本页补的是它的**对偶命题**：当跳的粒度细到"神经元"、且数量固定时，**parallel 前提不再需要，且最坏情况算力被真正降低**。两页合起来回答了"动态计算到底能不能服务 deadline"这个问题。
- **宿主结构**：[[wiki_low_latency/concepts/2107.05429-dual-path-recurrent-context]] 解释了 DPCRN/DPRNN 为什么天然有大量并行 RNN——这正是 Skip-RNN 类方法的前提。D-GRU 的 DPRNN 骨干也来自这个家族，但它**不依赖**并行性。
- **算力-延迟的三重分野**：[[wiki_low_latency/concepts/严格因果与算法延迟]] 与 [[wiki_low_latency/concepts/低时延前端与延迟账本]] 强调"算法延迟 ≠ 计算耗时 ≠ 端到端"。本页要补第三条：**"算力下降" ≠ "延迟/功耗下降"**——而且这一条在 D-GRU 上比在 Skip-DPCRN 上更微妙：D-GRU 的算力**确实**在 MAC 口径下是常数，但"常数"与"可兑现"之间仍隔着一次硬件测量。
- **同为"利用时间冗余降算力"**：[[wiki_low_latency/concepts/2411.02019-slowfast-ssm]] 用双速率分支与状态转移调制利用时间冗余；本页用隐状态慢变跳过部分神经元。一个改的是**状态更新的速率**（跨帧），一个改的是**状态更新的宽度**（层内）。
- **最严因果口径**：[[wiki_low_latency/sources/2026/LaCo-SENet 2026]] 给出逐层 padding 分配式与状态选择算子，是本库因果审计的最高标准。用它的尺子量 D-GRU：STFT 帧锚定、三个骨干的 padding、DPRNN 的 chunk 长度**全部未报告**——因此连"逐层可核验"这一关都过不了。本页把 D-GRU 记为 `paper-claimed-causal`。
- **同思路的另一实现**：[[wiki_low_latency/sources/2026/RT-Tango 2026]] 用 **FRS 固定间隔**复用 mask 来省算力，并在消融里**对比过 learned skipping / SkipRNN / TinyLSTM**（learned skipping 反而伤害 MN-DNN）。这与本页"固定比例/固定间隔优于学出来的波动"的命题**互相印证**——两条独立工作都发现"可预测的固定模式"比"学出来的动态模式"更适合硬件。
- **缺失维度**：[[wiki_low_latency/concepts/低 SNR 人声保留评估]] 提供本篇完全空缺的验收字段。

> [!question] 当前缺口
> 这套机制证明了"固定比例的神经元级稀疏在**质量**上可行"（$P\ge50\%$ 时 PESQ 差异不显著），但没有证明：
> ① **每步算力恒定可兑现为墙钟时间恒定**（无任何硬件测量）；
> ② 阈值型 select gate 相对 top-$A$ 的质量代价（论文从未评估，明确留作 future work）；
> ③ 长流下"部分分量长期陈旧"的漂移量级；
> ④ 与约 2 ms 硬约束的距离（论文**完全没有延迟数据**）。
> 本库认为最值得直接做的改进是：**把 top-$A$ 的选择实现成"固定数量 + 局部连续块"**（例如在每 $K$ 个连续神经元里固定选若干个），这样既保住数量恒定、又让访问模式变成规则的连续块，从而把 MAC 计数上的节省真正转化为墙钟时间上的节省。这个想法在 D-GRU 论文里没有被考虑过。
