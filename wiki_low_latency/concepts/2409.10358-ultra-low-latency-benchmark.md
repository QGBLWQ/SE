# 2409.10358 - 超低时延语音增强统一基准

## 简洁定义

该概念指 2409.10358 建立的统一低时延语音增强比较方式：固定 CRUSE 增强主干、训练数据和评测流程，再分别替换窗口、可学习分析/合成变换、FBE、未来帧预测、Mamba 和模型容量。它的价值是把“低时延技巧本身”和“训练、模型规模、数据协议差异”拆开；它不是一个单独模型或一个端到端硬件标准。

## 基本信号与变换

单通道输入为：

$$
x(t)=s(t)+n(t),
$$

其中 $s(t)$ 是目标语音，$n(t)$ 包含加入噪声和混响。论文把第 $k$ 个重叠段变换为：

$$
X_k=(x_k\circ w_a)\cdot W_{\mathrm{fft}},
$$

并以：

$$
\hat{s}_k=(\hat{S}_k\cdot W_{\mathrm{ifft}})\circ w_s
$$

完成合成。$L_a,L_s$ 分别是分析/合成段长，$P$ 是 frame shift，$w_a,w_s$ 是窗口，$W_{\mathrm{fft}},W_{\mathrm{ifft}}$ 是分析/合成基函数矩阵，$X_k,\hat S_k$ 是段级表示，$\hat s_k$ 经 overlap-add 形成 $\hat s(t)$。

对 overlap-add，论文明确写出：

$$
L_{\mathrm{alg}}=L_s-P.
$$

它是算法/重合相加项，不包括模型执行和 I/O。

## 低时延账本

| 层次 | 要记录什么 | 2409.10358 的状态 |
|---|---|---|
| 分析/合成 | iWin/oWin、窗口类型、$L_a,L_s$ | Table I 给出 20、10、6、5、3 ms 等；主干为 sqrt-Hann，asym 使用长分析窗/短合成窗 |
| 帧移/缓冲 | $P$、overlap、buffer latency | 论文给出 $P$ samples frame shift；未来预测在 50% overlap 时剩 buffer hop；各设置样本数未给全 |
| 算法延迟 | $L_s-P$ | 明确给出；表中 Latency 是 20/10/5/3/2.5 ms 等设计口径 |
| 模型计算 | MACs/sec、参数、量化 | 表 I 给出 parameters/MACs；Mamba MACs 为 - |
| 运行时 | RTF、p50/p95/p99、deadline | 未报告 |
| 端到端 | ADC/DMA、input/output buffer、DAC | 未报告 |
| 流式恢复 | batch=1、warm-up、state reset、underrun/overrun | 未报告 |
| 样本因果性 | padding、归一化、缓存、最新可读输入 | 只明确写 causal 3x3 deep filters；不足以给 strict-causal certificate |

本 Wiki 的端到端审计式可写为：

$$
L_{\mathrm{capture\to play}}
=L_{\mathrm{ADC/DMA}}+L_{\mathrm{inbuf}}+L_{\mathrm{alg}}
+L_{\mathrm{compute,p99}}+L_{\mathrm{outbuf}}+L_{\mathrm{DAC}}.
$$

这条式子是本库的审计账本，不是 2409.10358 报告的测量结果；本文只给出了 $L_{\mathrm{alg}}$ 和表格 latency，没有给出其余项。

## 基准比较轴

| 比较轴 | 论文操作 | 关键含义 |
|---|---|---|
| 对称窗 | sym-20/10/5/3 | 固定 CRUSE 时，短窗导致质量下降、MACs/sec 上升 |
| 非对称窗 | asym-10/5/3 | 长分析窗、短合成窗；强 CRUSE 上优势不稳定，弱 U-Net 上更明显 |
| 可学习窗/变换 | Learn-asym-10/5/3 | 中高时延点更强；3 ms 上差距变小 |
| 模型容量 | original/medium/large、same-compute | large 3 ms 可接近 original 20 ms，但模型和 MACs 显著增大 |
| FBE | FBE-10/5/2.5 | overlap-save 低时延路线，表内质量低于 overlap-add |
| 未来帧预测 | mapping 与 predict | 模拟数据略有收益，DNS blind 更差；受 mapping target 限制 |
| 时序模块 | GRU 与 Mamba | Mamba 20 ms 尚可，5 ms 明显退化；计算量未给 |

## 结果与解读

表 I 的代表性证据：

| 配置 | DNS blind OVR | Sim OVR / PESQ / siSDR | Model / MACs |
|---|---:|---:|---:|
| A1 sym-20ms | 2.79 | 2.46 / 2.22 / 10.52 | 0.625M / 230.27M |
| A4 sym-3ms | 2.74 | 2.36 / 2.18 / 9.65 | 0.625M / 1.54G |
| D3 same-compute-3ms | 2.67 | 2.33 / 2.05 / 9.03 | 0.142M / 230.33M |
| F6 large asym-3ms | 2.80 | 2.42 / 2.27 / 10.34 | 8.67M / 10.95G |
| C1 Learn-asym-10ms | 2.83 | 2.47 / 2.31 / 10.84 | 0.625M / 460.53M |
| E3 Mamba-5ms | 2.63 | 2.33 / 2.15 / 9.71 | 0.642M / 未报告 |
| H3 FBE-2.5ms | 2.62 | 2.27 / 1.89 / 7.80 | 0.637M / 1.098G |

结论强度应限制为：

- 论文直接支持：统一 CRUSE 下，降低窗/时延通常损失质量；固定模型时 MACs/sec 增加；足够大的模型可恢复短窗损失；强 CRUSE 下非对称窗收益不稳定；Mamba 在低时延点退化；未来预测受 mapping target 限制。
- 论文不支持：某配置在真实设备端到端小于 5 ms；某方法在所有低 SNR 噪声中更能保留人声；Mamba 在本实验中一定更低算；MACs 数字等于 RTF 或 deadline 通过。

## 人声保留与噪声抑制审计

论文报告 DNSMOS 的 SIG、BAK、OVR 和 simulated data 上的 STOI，并给出 PESQ、siSDR；这些可以观察整体信号/背景质量和可懂度。例如 A1 到 A4 的 DNS blind SIG/BAK/OVR 从 3.18/3.78/2.79 变为 3.12/3.77/2.74。

但没有报告：

- -10/-5/0/5 dB 分层或按 SNR 的 SIG-BAK 曲线；
- babble、竞争说话人、瞬态噪声、未见噪声和混响的独立结果；
- false-suppression、SPP/VAD calibration、ASR WER、F0/formant/prosody continuity、voiced-energy；
- 人工 MOS/A-B 听测；
- 计算 p99、deadline miss 和长流恢复。

所以“质量更高”必须写成对应测试集、指标和时延口径下的局部结论，不能把 BAK 或 OVR 的改善等同于低 SNR 人声保留。
