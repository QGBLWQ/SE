# 实验：算力对齐 × 真机延迟实测（名义 MACs 的排序失效）

## 来源

[[wiki_low_latency/sources/2026/Early Exit Compute-Matched 2026]]（arXiv:2609.29867，GN A/S + DTU，2026-09-24）。

它是本库**算力证据最硬**的一篇：真机 **STM32N6570-DK**（Neural-ART NPU @1 GHz + Cortex-M55 @800 MHz）、
**post-training int8**（per-channel + entropy calibration）、**十张完整可部署图**、逐张实测 **ms/frame**。
量纲是**时间**而不是吞吐，因此它比本库任何一篇（包括 FastEnhancer 的单线程 RTF）都更接近 deadline 议题。

它给本库留下的是**三条方法论资产**，而不是一个模型：

| # | 资产 | 硬数据 | 它推翻了什么 |
|---|---|---|---|
| A | **名义 MACs 在真实 NPU 上给出错误排序** | 十图 **µs/MMAC 82–137（1.7×）**；$(H{=}32,R{=}2)$ vs $(H{=}64,R{=}1)$ **MMAC/s 同为 7.30 却差 33 % 时间**（1.001 vs 0.751 ms）；$(H{=}96,R{=}1)$ **+21.4 % MACs ⇒ −14.9 % 时间** | 推翻"MACs ↓ ⇒ 更快"——**出现双向反例**，不是单调偏差 |
| B | **算力对齐是动态算力论文的入场券** | 修复前 routed **2.719 PESQ @ 8.48 MMAC/s** vs 同算力静态前沿约 **2.60**；**修复后差 <0.01 PESQ**（8.48 / 12.18 / 20.22 MMAC/s 上 **+0.009 / −0.001 / +0.007**） | 推翻"早退/动态深度有效"——不做对齐，动态策略**必然**看起来有用 |
| C | **评测协议会伪造动态收益** | 常见离线协议把 routed 输出算成 **gated sum**，**即使某 exit 未被选中也在更新其状态**；改为"跳过 stack 状态不更新"后代价仅 **−0.005±0.011 PESQ / 0.14 dB SI-SDR**，路由决策两 arm **bit-identical** | 推翻"离线评测足以代表在线动态执行" |

机理（论文归因）：**深度每多一个 stack 就多一次 accelerator launch 与一次流水线启动开销，宽度能被单次 launch 更好摊销**——
注意这与 FastEnhancer 的归因（**算子可融合性 / 内存操作**）**不是同一条**。
两篇是"MACs ≠ 速度"这个论断的**两个独立机理证据**，可并列引用而互不替代。

## 假设

### 假设 1（机理层）：`µs/MMAC` 的跨结构离散度可由「accelerator launch 次数」预测

本篇给出的三条反例（1.7× 离散度、同 MMAC/s 差 33 %、MACs 多却更快）**都指向同一个变量**：
一张图被切成了多少次 NPU 调度。深度增加 ⇒ 串行的 launch 增多 ⇒ 每次 launch 的固定开销（DMA 搬运、
权重预取、流水线填充/排空）无法被分摊。宽度增加 ⇒ 单次 launch 内的 MAC 数变大 ⇒ 固定开销被摊薄。

**可证伪的预测**：对同一 family 的一批配置，若把 **launch 次数** 作为自变量、**ms/frame** 作为因变量，
拟合优度应显著高于用 MACs 作自变量。本篇的十图提供了 10 个点——**但论文自己没做这个回归**，
所以这是本库可以直接补上的一格。

> **注意边界**：本篇**未给出十图的 launch 次数**（只说"每多一个 stack 多一次 launch"），
> 所以 `launch 次数` 在本库当前只能**推读**（由 stack 数 + 是否有分支得到），证据等级低于 ms/frame 本身。

### 假设 2（协议层）：本库第 4 批的「平均省算力」在算力对齐后必须下调

本库第 4 批（2026-09-22）收录 Skip-DPCRN / D-GRU 时，overview 第 5 条只要求"报平均/峰值/分布"。
本篇表明这**还不够**：还要问静态基线是否**同配方重训**、工作点是否**同算力**、深度方向是否**已验证单调**。
本篇的示范是：把 knee target 从"当前 exits"定义（不要求质量随深度单调），再用 **2000 步、只动 4×33k 参数的 heads-only 微调 + 单调性正则**
把"深 exit 反而更差"这一信号抽掉——**抽掉之后动态收益几乎消失**。

**可证伪的预测**：若 Skip-DPCRN / D-GRU 补上同配方重训的静态基线，其"平均省 33 %"对应的**质量等价点**会明显后移，
即"省算力"主张需下调；若不下调，则说明这两篇的动态收益不来自"回避有害路径"这一机制，与本篇机理不同。

### 假设 3（审计层）：动态执行模型的离线模拟必须与在线执行等价

本篇的做法（**跳过 stack 状态不更新**）在本库是**正面样本**；
库内需要并列的对照面是 **PSMSE 的 50 % OLA** 与 **RT-Tango-OS 的无限预热评测**。
本篇的干净之处在于它**同时给了路由决策的 bit-identical 声明**——这比只给最终指标强得多。

**可证伪的预测**：对库内做整步跳过 / 神经元稀疏的模型，重做"离线 gated 代理 vs 在线真执行"的对照，
差额应落在本篇给出的量级（约 0.005 PESQ / 0.14 dB SI-SDR）附近；若远超，说明该模型的离线评测把动态收益放大到了不可引用的程度。

## 方法

### 阶段一：算力证据等级表（**不需要新硬件，可立刻做**）

逐模型填下表，覆盖 `wiki_low_latency` 全库 29 篇：

| 等级 | 判据 | 本库预计落位 |
|---|---|---|
| **L0** | 只有参数量 / 解析 MACs | D-GRU、多数"低复杂度"论文 |
| **L1** | 有 RTF，但无硬件/运行时/口径说明 | 库内多篇 |
| **L2** | RTF + 硬件 + 运行时 + chunk 定义（**吞吐**量纲） | FastEnhancer、LaCo-SENet、Tsunoo 2024 |
| **L3** | 目标芯片真机、量化后、**ms/frame**、逐图/逐配置实测 | **本篇（唯一）** |

**判据纪律**：等级只由**证据形式**决定，与论文声称的"低复杂度"无关；
**L0/L1 禁止参与速度排序**，只能记录数值。这张表本身就是对 overview 第 10 条的落地，
它的用途是**一次性说明"为什么本库不能给出速度排行榜"**——比逐篇解释省事。

### 阶段二：审计清单补第 ⑧ 项并回填

FastEnhancer 的结构审计清单目前 7 项（时间轴 kernel / 归一化可融合性 / 注意力 KV cache /
global pooling / 数据相关访问 / 算力是否固定 / 全序列统计）。
本篇揭示第 **8** 项：**accelerator launch / 调度次数是否随输入或配置变化**。
**判"危险"条件**：是 ⇒ MACs 与实际耗时脱钩。

回填顺序：Skip-DPCRN → D-GRU → FastEnhancer（第 6 批自己也需要，因为它的 DPT/RNNFormer 切换会改变 launch 结构）。

### 阶段三：算力对齐 + 同配方重训（**门槛，不是可选**）

对本库任何"输入相关动态算力"模型，必须能回答三个问题（overview 第 12 条）：

1. 静态基线是否**同配方重训**过？
2. 是否在同一 **MMAC/s（或同一 ms/frame）**工作点上比较？
3. 深度方向的**单调性**是否被验证（且有残余违规率 / 收敛曲线）？

任何一句答不上来 ⇒ 该动态收益记为**未归因**。本篇自己在这一关上也有缺口：
它承诺的 "**seed spreads**" 从未兑现，而核心结论正压在 **0.01 量级**的 PESQ 差值上——
**这比第 6 批"5 seeds 只报均值"的同类问题更严重**（后者至少报了均值）。

### 阶段四：真机 ms/frame 实测（**需硬件**）

挑 **3–4 个 MMAC/s 接近但结构不同**的配置（可利用本篇 Table 1 的 $(H, R)$ 网格做候选），
在同一 NPU、同一量化流程、同一运行时下测 ms/frame，回归 `ms/frame ~ launch 次数` 与 `ms/frame ~ MACs`，
比较两者拟合优度。

## 预期结论与验收标准

| # | 预期 | 验收标准 |
|---|---|---|
| 1 | 全库 29 篇可被 L0–L3 完整分级 | 无一篇落在"无法判定"；每篇标注证据出处（页/表号） |
| 2 | `launch 次数` 比 `MACs` 更能预测 ms/frame | 同一硬件同一批配置上，$R^2$ 显著更高（阶段四） |
| 3 | 第 4 批"平均省算力"在算力对齐后下调 | Skip-DPCRN / D-GRU 的等价工作点后移，给出具体 ΔPESQ |
| 4 | 离线 gated 代理 vs 在线真执行的差额 ≈ 0.005 PESQ 量级 | 若差额 >0.02 PESQ，则该模型的离线评测结果**禁止**被本库引用 |
| 5 | 全库仍无一篇满足约 2 ms 硬约束 | 本篇 hop = 16 ms（256 @16 kHz），**不是 2 ms 候选**；延迟账本仍为空（无算法延迟数字） |

## 与本篇证据边界的一致性声明

本实验在引用本篇时**必须同时保留**下列边界（详细见 source 页 `[!warning]`）：

- **无算法延迟数字**；hop = 256 @16 kHz = **16 ms**；**STFT/iSTFT/masking 留在 host、未计入 Table 1/2**。
  且 **STFT 的 center 锚定未报告**——若 host 侧用 `center=True`，则"当前帧"本身已含未来样本
  ⇒ 本篇的因果性是**模型级**而非**系统级**。**论文没有回答这个问题**。
- **无 p50/p95/p99、无 deadline miss、无 underrun、无峰值内存/SRAM、无功耗**（动机是 battery budget 却零功耗数据）。
- **全模型参数量未报告**（只有 exit heads 的 4×33k）；**无长流 / state reset / warm-up 报告**。
- **人声保留只有 whole-clip SI-SDR + wideband PESQ**：无 DNSMOS SIG/BAK、无 WER/ASR、无负 SNR 分层（仅 Fig. 4 一条 0.46 dB 示例语句）、无 false-suppression / F0 / prosody。
- **论文自陈局限**：主张**仅限语音密集数据集**（VoiceBank–DEMAND）；长停顿工作负载不在研究范围内，
  而"router 在稀疏工作负载上是否更有价值"被列为**重要下一步**。
- **venv 状态**：`venue_status: preprint_only`（纯 arXiv，无 Comments、无 Journal-ref）。
