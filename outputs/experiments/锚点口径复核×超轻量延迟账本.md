# 实验：锚点口径复核 × 超轻量模型的延迟账本空白

## 来源

[[wiki_low_latency/sources/2024/GTCRN 2024]]（ICASSP 2024, pp. 971–975, DOI `10.1109/ICASSP48485.2024.10448310`）。
2026-09-27 由用户提供 PDF 后补摄（此前因 **IEEE 付费墙 + 无 arXiv 版**而无法合法获取）。

**补摄它产生的最大产出不是"多了一个模型的页面"，而是一个跨页面的发现**：
GTCRN 是本库**被引用次数最多的库外锚点**（`FastEnhancer` / `RT-Tango` / `PSMSE` / `muNet` 四篇同时引用），
但在补摄之前，本库**只能通过这四篇的二手转述认识它**。补摄后立刻暴露：

| 问题 | 具体 |
|---|---|
| **参数量/算力有三套口径** | 原文 23.7 K / 39.6 MMACs/s（自洽）· FastEnhancer 24 K / 40 M（≈四舍五入）· muNet 48 K / 33 MMACs（**不可调和**，参数 2.03× 而 MACs 0.83×） |
| **页码有二套口径** | 971–975（GTCRN 自身页脚，一手）· 10286–10290（Early Exit 的引用著录，二手）⇒ 已定案前者 |
| **延迟账本为零** | 无 RTF、无 ms/frame、无硬件、无量化、无端侧实测；唯一时延锚点是 **hop 16 ms**；**STFT center 未报告** |
| **因果性只有一句声明** | `so that the causality of the model can be guaranteed`（针对 inter-frame 单向 GRU），**无逐层 padding / state certificate** |

## 假设

### 假设 1（数值层）：锚点数值存在多套口径是**常态**，而非 GTCRN 的偶然

本库的"效率比较"大量依赖库外模型的参数量与 MACs。这些数字的**来源有三种**：① 原论文声称值（常按设计算，而非 `sum(p.numel())`）；
② 引用方的复现值（受 checkpoint、运行时、是否含 STFT 影响）；③ 官方实现的实测值。
**三者可以互不相同**——GTCRN 就是三者齐全且互不相容的样本。

**可证伪的预测**：把库内被 ≥2 篇同时引用的模型逐个登记后，**存在矛盾的比例应显著大于 0**。
若发现绝大多数锚点只有单一口径来源，则本假设被削弱，本库的引用链风险也随之降低。

### 假设 2（证据层）：「超轻量」档的"轻量 ⇒ 快"假设，在本库内**从未被一手实测验证过**

本库讨论"超轻量"时，默认"参数量/MACs 小 ⇒ 端侧可跑"。但：
- **GTCRN（本档锚点）零速度数据**；
- 本档的速度数字（RTF 0.060 / 0.042）**全部来自 FastEnhancer 的第三方复现**；
- 而 FastEnhancer 自己又证明**"MACs 不是速度"**（BN→LN 零算术变化却慢 27 %）。

⇒ 本档存在一个**逻辑缺口**：**用"低 MACs"论证"能上端侧"，而论证该命题的方法论文正说"MACs 不能论证这一点"。**

**可证伪的预测**：给 GTCRN 做同硬件、同运行时、同量化的 ms/frame 实测后，
它与 FastEnhancer-B（92K/262M）的**耗时比**应**远小于**它们的 MACs 比（6.5×），
因为后者（更宽的层、更少的串行依赖）在 NPU 上摊薄固定开销的能力更强——**这正是 Early Exit 轮已经给出的机理（accelerator launch 次数）**。

### 假设 3（记账层）：锚点数值一错，整条引用链一起偏，但**结论方向常不变**

GTCRN 的算力在 33–40 MMACs/s 之间浮动（±20 %），而 FastEnhancer-B 是 262 M —— **差 6.5–7.9×**。
**无论取 33 还是 40，"MACs 高 6.5× 却 RTF 低 2.7×"这个结论方向都不变**；
但若某处论证恰好卡在临界区（如"两者算力相当"），则**口径一换结论就翻转**。

**可证伪的预测**：库内多数结论方向不变，**但至少有一处会因口径变更而翻转或需要弱化措辞**。

## 方法

### 阶段一：建立锚点清单（**不需要新硬件，可立刻做**）

新建 `wiki_low_latency/锚点清单.md`，逐模型登记四个字段：

| 字段 | 要求 |
|---|---|
| **原文声称值** | 尽量从**一手 PDF**取；注明页/章节 |
| **各引用方给的值** | 逐个列出（引用方 + 值 + 该引用方的脚注口径，如"官方 checkpoint"/"作者重训"） |
| **是否可调和** | 计算相对误差；方向相反的直接判"不可调和" |
| **一手证据来源** | 是 PDF 页脚 / 正文 Table / 官方 repo / 第三方转述——**四者可信度递减** |

已知候选：**GTCRN**（4 篇引用）、**DPCRN**、**RNNoise**（问题：库内两处用法口径不同，GTCRN 表用官方 repo 代码测）、
**DeepFilterNet2**、**FSNet / FSB-LSTM**、**S-DCCRN**、**Conv-TasNet**。

### 阶段二：口径复核（回填既有页面）

对库内所有"X K / Y M"型结论逐个复核，**优先级按被引用次数排序**：

1. **FastEnhancer 的「262M vs 40M，MACs 高 6.5× 却快 2.7×」**（被引用 ≥6 次，本库第 6 批的核心论证）；
2. **RT-Tango 的「GTCRN 16 ms→48.98 / 4 ms→197.5 MMAC/s」**（分布式、4 麦、mask 作用于本地参考通道，**与单通道 39.6 不是同一配置**）；
3. **PSMSE 的「23.7K–79K 参数」区间**（与原文一致 ✓）；
4. **muNet 的竞品表**（48 K/33，已加 `[!contradiction]`）；
5. **Early Exit 的「极轻量端参照」**（页码已定案）。

### 阶段三：给 GTCRN 补实测（**需硬件**）

GTCRN 是"超轻量"档的锚点，却**零速度数据**。补一臂：

- **同硬件、同运行时、同量化**下测 GTCRN 与 FastEnhancer-B 的 ms/frame；
- 记录 **accelerator launch 次数**（GTCRN：encoder 2 Conv + 3 GT-Conv，decoder 镜像，G-DPRNN 内含 4 个 GRU 组 ⇒ **串行深度比 GTCRN 的"分组"外表看起来要多**）；
- 检验假设 2 的预测：**耗时比 ≪ MACs 比**。

### 阶段四：确定 GTCRN 的 STFT 锚定（**可离线做，但需查代码**）

GTCRN 的 hop 16 ms 是**唯一时延锚点**，而 **center 未报告**：
- 若 `center=True` ⇒ 前端含 16 ms 未来样本 ⇒ 算法延迟 ≈ 32 ms；
- 若 `center=False` ⇒ ≈ 16 ms。
**论文未回答**。**唯一确定途径是查官方 repo `github.com/Xiaobin-Rong/gtcrn` 的 STFT 实现**（本库当前无网络，记为待办）。
**在确定之前，本库对 GTCRN 的算法延迟一律记「≈16 或 ≈32 ms，双向不确定」。**

## 预期结论与验收标准

| # | 预期 | 验收标准 |
|---|---|---|
| 1 | 库内 ≥2 篇同时引用的锚点 ≥6 个 | 每个都有原文声称值 + 引用方值 + 矛盾判定 |
| 2 | 至少 1 个锚点存在不可调和的口径矛盾 | 给出相对误差与方向；GTCRN 已满足（1/1） |
| 3 | 复核后多数结论方向不变，≥1 处需弱化措辞 | 列出具体条目与新的措辞 |
| 4 | GTCRN 的耗时比 ≪ MACs 比（6.5×） | 阶段三实测给出具体比值 |
| 5 | 本库仍无一篇满足约 2 ms 硬约束 | GTCRN hop 16 ms，**不是 2 ms 候选**；延迟账本仍为"双向不确定" |

## 与本篇证据边界的一致性声明

引用 GTCRN 时**必须同时保留**下列边界（详见 [[wiki_low_latency/entities/GTCRN]]）：

- **venue 为本库最高档**（ICASSP 2024 正式出版，pp. 971–975，DOI `10.1109/ICASSP48485.2024.10448310`）——
  **与第 6、7 批的纯预印本形成对照**：**venue 可信度与数据完整度无关**，本篇是"正式出版但延迟账本为零"的样本。
- **无 RTF / 无 ms/frame / 无目标硬件 / 无量化 / 无端侧实测 / 无 p99**；算力证据停在 **L0（名义 MACs）**。
- **STFT center 未报告**、逐层 padding 未报告、DD-Conv2D 时间感受野未给（本库推得 kernel 时间维 3 × dilation 1/2/5 ⇒ 单链累计 17 帧，**是推算非论文值**）。
- **全文无 limitations / future work 章节**；Table 2/3 有 10 处空格子；**RNNoise 的数字口径不同且脚注只挂在 Table 3**。
- **无随机种子、无方差**：Table 1/Table 3 多处 `+0.01` 量级的结论（PESQ 1.89→1.91、P.808 3.43→3.44）**无法判断显著性**。
- **人声保留缺口**：Table 3 的 **SIG = 3.00 与 RNNoise 完全相同，且两者都低于 Noisy 的 3.20** ⇒ 收益全部来自 BAK（+0.45）与 OVRL（+0.17）。
  **这正是必须报告 SIG–BAK trade-off 的情形，而论文只写了 "outperforms by a wide margin"。**
- **与 FastEnhancer 的直接冲突**：GTCRN 是子带路线代表，FastEnhancer §2.2 点名批评该路线抬高 RTF；**GTCRN 全文无 RTF，无法回应**。
  第三条批评来自 PSMSE（容量受限）。⇒ **三条评价必须并读。**
