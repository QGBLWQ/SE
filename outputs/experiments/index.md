## 跨实验验收要求

由 2026-09-20 / 2026-09-22 / 2026-09-24 / 2026-09-26 / 2026-09-27（两轮：Early Exit + GTCRN）/ 2026-10-07 **七轮**摄取提炼，适用于上述所有实验：

1. **算法延迟必须与 chunk size 和 RTF 一起报告。** LaCo-SENet 的 12.5 ms 只在 $C=1$ 成立，
   而该配置 RTF 4.59；要 RTF<1 需 $C\ge 7\text{–}12$，总时延升至约 62.5 ms。
   单独报「算法延迟」会系统性低估真实预算。
2. **在线递归统计必须按冷启动评测。** RT-Tango-OS 的在线 SCM 用「把同一段混合重复到收敛、
   只算最后一次」评测，等于无限预热。任何带在线统计（SCM / EMA / 自适应噪声估计）的实验
   都应额外报告**收敛前曲线**与「第 1 秒」的指标。
3. **「流式」必须写明状态语义。** 是跨帧缓存状态（如 RT-SEMamba 的固定 SSM state），
   还是逐帧重置 + OLA 拼接（如 PSMSE）？两者的长流一致性、warm-up/flush 和伪影风险完全不同。
4. **因果性判定用更严口径。** 「自称 unidirectional」不足以标 `strict_causal`；
   需给出逐层 padding / 归一化统计 / 状态写入范围的证据（参照 LaCo-SENet Eq. (1)(2)(5)）。
5. **输入相关的动态算力必须报峰值，不能只报平均值。** Skip-DPCRN 平均省 33% MACs，
   但帧级更新率近似高斯，**峰值算力只降约 15%**——实时硬件按最坏情况预留，
   所以「平均省 33%」不是可兑现的预算。D-GRU 正是抓这一点改用固定比例。
   任何动态算力实验至少要给 **平均 / 峰值 / 分布**，并说明硬件是否需按最坏情况配置。
   注意 **MAC 恒定 ≠ 墙钟恒定**：top-A 这类数据相关算子在真实硬件上有 gather/scatter 与分支开销。
6. **小效应量的增益必须配统计证据。** Tsunoo 2024 的核心结论是 **+0.05 PESQ**（因果下语义预测的增益），
   而整个 PESQ 报告精度就是 0.01，且论文**无方差、无置信区间、无显著性检验、单次运行**。
   凡引用 ≤0.05 量级的增益，都必须标注「未经显著性检验」，实验里也要带种子方差。
   同轮的其他小效应量：codebook 隐向量 vs 索引 +0.02、因果 SSL 特征本身 +0.03。
7. **辅助任务必须做「随机目标」对照臂。** 任何"多任务辅助监督带来增益"的设计，
   都要加一臂**与目标无关的随机监督**，以区分「增益来自有用信息」与「增益来自正则化」。
   Tsunoo 的 Table IV 是干净的条件对照（因果 +0.05 / 非因果 0.00），但**没有做这一臂**。
8. **"因果化"必须交代计算模式：重算、缓存、还是重训。** 把非因果预训练模型截断成因果
   （Tsunoo Eq. 5：限制输入为过去帧 + 取末帧）在流式下是**重算型**，代价 $O(T^2)$ 量级。
   只说「限制为因果」而不交代计算模式的系统，其延迟账本应视为**空**。
9. **RTF 必须连同硬件 + 运行时 + 是否含前端一起记录，且不得跨平台外推比例。**
   FastEnhancer 2025 给出一组同模型零算术变化的对照：BN→LN 在参数量（92K）与 MACs **完全不变**下
   RTF 0.022→0.028（Xeon **+27%**）/ 0.026→0.029（M1 **+12%**）；
   而时间轴 kernel 1→3 是 Xeon **+27%** / M1 **+42%**。
   **两个平台给出的相对代价方向都不一致** ⇒ "可融合性的收益"不是常数，必须绑定运行时报告。
10. **"低复杂度"（参数量 / MACs）不能替代实测 RTF，两者应分栏呈现并给出秩相关。**
   FastEnhancer-B 用 **262M MACs** 取得 RTF 0.022，而 GTCRN 用 **40M MACs** 却是 0.060——
   MACs 高 6.5×、RTF 低 2.7×。**因此任何以"低 MACs"为主张的实验，必须同时给出实测 RTF**，
   并注明硬件、运行时、线程数与是否含 STFT/iSTFT。反之，**RTF 也不能替代 deadline 证据**：
   即便 RTF = 0.012，仍需 p50/p95/p99、deadline miss、underrun/overrun 才能认证实时性。
   > **⚠️ 口径补注（2026-09-27，GTCRN 补摄后）**：此处 GTCRN 的 **40M MACs** 与 **0.060 RTF** 来自 **FastEnhancer 的复现**（脚注 a = 官方 checkpoint）。
   > GTCRN 原文声称 **39.6 MMACs per second**（≈40，一致），但 **μNet 引用官方实现为 33 MMACs**，
   > 且**官方 repo 更新值为 48.2 K / 33.0**。⇒ **GTCRN 的算力在库内有 39.6 / 40 / 33 三套口径**。
   > **本条的结论方向不受影响**（33–40 M 同量级，均远低于 262 M），但**做秩相关或回归时必须声明用哪一套**。
   > 详见 [[wiki_low_latency/entities/GTCRN]] 的 `[!contradiction]` 与 overview 判定口径第 14 条。
11. **「算力证据等级」必须独立于「延迟证据等级」标注，且 L0/L1 禁止参与速度排序。**
   Early Exit Compute-Matched 2026 是本库唯一到 **L3** 的论文（STM32N6570-DK、post-training int8、
   **ms/frame** 量纲、十张完整可部署图逐张实测），而库内多数论文停在 **L0**（仅解析 MACs）。
   分级：**L0** 解析 MACs/参数量 → 只能比复杂度；**L1** 有 RTF 但无硬件/运行时/口径 → 只能"作者称能实时"；
   **L2** RTF + 硬件 + 运行时 + chunk 定义（**吞吐**量纲，如 FastEnhancer / LaCo-SENet）→ 可同口径横比；
   **L3** 目标芯片真机、量化后、**ms/frame**、逐图实测（如本篇）→ 可支撑速度排名。
   注意**即便 L3 也只认证"排名"，不认证"实时"**——本篇无 p50/p95/p99、无 stall/miss。
12. **名义 MACs 在真实加速器上可能给出错误排序——必须报「µs/MMAC 离散度」，而非只报 MMAC/s。**
   本篇十图 **µs/MMAC 差 1.7×（82–137）**，并出现两类**双向**反例：
   $(H{=}32,R{=}2)$ 与 $(H{=}64,R{=}1)$ **MMAC/s 完全相同（7.30）却差 33 % 时间**（1.001 vs 0.751 ms/frame）；
   $(H{=}96,R{=}1)$ **MACs 多 21.4 % 却快 14.9 %**。机理是 **accelerator launch 次数**——
   深度每多一个 stack 就多一次 launch，宽度能被单次 launch 更好摊销。
   因此结构审计清单在原 7 项之外补第 **⑧** 项：**accelerator launch / 调度次数是否随输入或配置变化**
   （是 ⇒ MACs 与实际耗时脱钩）。**第 5 条（平均算力 ≠ 可用算力）与第 9 条（RTF 非 deadline）
   都未覆盖"算术量与真实时间之间的排序一致性"，本条补上这一格。**
13. **动态算力实验必须先做「算力对齐」，否则收益不可归因（三问门槛）。**
   本篇证明：只要拿动态策略去比**未经调优的静态基线**，任何动态方法都会"看起来有用"。
   入场三问：① 静态基线是否**同配方重训**过？② 是否在同一 **MMAC/s（或同一 ms/frame）**工作点上比较？
   ③ 深度方向的**单调性**是否被验证（且有残余违规率 / 收敛曲线）？任一句答不上来 ⇒ 收益记为**未归因**。
   净值：修复前 routed **2.719 PESQ @ 8.48 MMAC/s** vs 同算力静态约 **2.60**；
   修复后 **<0.01 PESQ**（8.48 / 12.18 / 20.22 MMAC/s 上 **+0.009 / −0.001 / +0.007**）。
   **本库第 4 批（Skip-DPCRN / D-GRU）按此门槛回填后，其"平均省算力"主张需下调。**
   注意本篇自身也**未兑现承诺的 "seed spreads"**，而结论正压在 0.01 量级上——**比第 6 批"5 seeds 只报均值"更严重**。
14. **动态执行模型必须审计「被跳过的模块状态是否被更新」——离线协议会伪造动态收益。**
   常见离线做法把 routed 输出算成 **gated sum**（用 gate 权重混合各 exit 输出），
   于是**即使某 exit 未被选中、其内部状态也在更新**：延迟与算力**不可信**，增益**虚高**。
   本篇改为"**跳过 stack 状态不更新**"，代价仅 **−0.005±0.011 PESQ / 0.14 dB SI-SDR**，
   且**路由决策在两 arm 间 bit-identical**（这个声明比只报最终指标强得多）。
   **实验要求**：任何动态执行类的"离线/在线一致性"声明，必须说明**离线模拟是否等价于在线执行**；
   只报 gated-sum 结果的，其动态收益**禁止**与整模型结果并列。
   **附带收获**：本篇明确"**被跳过的 stack 状态不更新 ⇒ 结构上不可能引入未来依赖**"，
   是本库对**动态执行下因果性**最清晰的一句工程交代，**可作为该情形的判据模板**
   （对照面：PSMSE 的 50 % OLA、RT-Tango-OS 的无限预热评测）。
15. **锚点数值必须先钉死口径再允许被引用；被 ≥2 篇同时引用的模型必须单列一页。**
   GTCRN 补摄（2026-09-27）暴露：库内**被引用次数最多的库外锚点**同时存在**三套参数量/MACs 口径**
   （原文 23.7 K / 39.6 M/s · FastEnhancer 24 K / 40 M · muNet 48 K / 33 M，后者参数 2.03× 而 MACs 0.83×，
   方向相反、**不可调和**），而本库**至少 6 条结论**建立在这些数值之上。
   **要求**：① 任何"X K / Y M"型比较必须标注**取哪一套口径及其来源**，
   并**禁止把不同口径的参数量与 MACs 混在同一次比较里**；② 发现不可调和的矛盾时
   **记 `[!contradiction]` 并全部保留，不择一采信**；③ 被 ≥2 篇引用的模型
   应建 `wiki_low_latency/锚点清单.md`，登记"原文声称值 / 各引用方值 / 是否矛盾 / 一手来源"。
   **注意**：口径复核后**"结论方向"常常不变，但"数值"必须重算**——
   GTCRN 的 33–40 M 均 ≪ FastEnhancer-B 的 262 M，"低 MACs 却慢"的方向不受影响，但 6.5× 这个比值需重算。
16. **引用即负有义务：引用了"算力 ≠ 速度"的文献，就必须报速度。**
   GTCRN 引用 ShuffleNetV2（其核心论点正是"MACs 不是速度的代理"）来支撑自身的轻量设计，
   却**通篇零 RTF / 零 ms/frame / 零硬件 / 零量化**——只给参数量与 MACs。
   **要求**：凡以"轻量 / 高效"为主张、并引用了效率反例文献的系统，其页面必须标注
   **"引用即负有义务而未履行"**，且其在任何速度维度的比较中应按 **L0（仅解析 MACs）** 处理、**禁止参与速度排序**。
17. **「平均算力的节省是否来自步内合并」必须单独声明，否则禁止推断峰值下降。**
   HALO（2026-10-07）把骨干内部帧率减半 ⇒ 平均 MAC/s **33.83 → 22.05（−34.8%）**，
   但**论文自陈"不降低峰值每步算力"**，因为**帧率恢复算子在同一次推理步里生成两个相邻帧**。
   ⇒ 这是库内第 4 种"平均算力 ≠ 可用算力"的机制，且是**结构性**的（此前三种 Skip-DPCRN / D-GRU / Early Exit 都是**动态**的）。
   **要求**：凡报"平均算力下降"的实验，必须回答"**节省是否来自步内合并/批内合并**"；是则**峰值不可推断下降**，
   且必须**同时报平均与峰值**两个数。
18. **「生成式/任何方法靠近实时」必须拆成吞吐（RTF）与算法延迟两轴，且延迟须声明是否含 $\tau_{enc}$。**
   SBM（2026-10-07）在两个轴上的结论完全相反：**吞吐 ✅**（一步、RTF 0.0048、比 SB-NCSN++(50) 快 160×）
   而 **算法延迟 ❌**（2–4 帧 lookahead + 30 ms 窗 ⇒ **50–70 ms**，距约 2 ms 目标 25–35 倍）；
   且其论文的 "under 40 ms" **恰好等于 4 帧 × 10 ms hop ⇒ 只含 $\tau_{sep}$，漏计 $\tau_{enc}$**。
   ⇒ 这一处误报正是 **LCA §3.2** 警告过的"漏报 buffering 项"现象，而该节的定义与库内口径**逐字同构**。
   **要求**：① 任何"实时/低延迟"主张**必须同时给出 RTF 与算法延迟**；② **必须声明延迟是否含 $\tau_{enc}$**；
   ③ **禁止**用 RTF ≪ 1 推断算法延迟合格。
19. **「用可学习模块替换手工先验」的主张，必须给出在退化条件下的对照；否则按"先验可能更优"记录。**
   跨层同构的两个证据（均来自 2026-10-07 第 11 批）：
   - **损失层**：TF Weighted Losses 的显式竞争先验 $\mathcal{L}_{SIR\cdot SP\cdot SF}$ 在 SSN 下稳定，
     而**纯可学习谱权重 $\mathcal{L}_{learn}$（用 ANSI SII 权重初始化）在 SSN 下所有 SIR 都差于基线**；
   - **架构层**：SEMamba++ 的 **FAN 频率周期先验**在质量与效率上都优于 **Transformer 的无偏置注意力**与 **Mamba 的序列顺序敏感**。
   ⇒ **结论：在语音这种强结构信号上，注入领域先验优于让模型从数据中学。**
   **要求**：凡"用可学习模块替换手工先验"的实验，**必须包含一个退化条件（谱形状噪声 / 域外数据 / 低 SNR）的对照**；
   只在温和条件下报告增益的，按"先验可能更优"记录。
20. **「加强人声保留权重」类实验必须给出按 SNR/SIR 分档的有效性曲线，不得只报平均值。**
   TF Weighted Losses 的实测：把权重压向"语音活跃但 SIR 低"的 bin，**在中高 SIR 最有效**，
   但 **极低 SIR（−8 dB）时反转**（基线在 band 6 以上更接近干净谱、基线 PA 略高），**SSN 下 0 dB 以下基线 WER 最低**。
   ⇒ **禁止假设"更低的 SNR 上更强的保人声加权更有效"**（候选机制：极低 SIR 下强竞争 bin 覆盖整个时频面 ⇒ 加权退化为近似均匀）。
   **要求**：① 分档报曲线（至少 0 / −5 / −10 dB 三档）；② 同时报**代价侧**（SDR / SAR / FW-SDR 的下降）；
   ③ 引入 **辅音 PA / 元音 PA（分列）** 作为人声保留的直接量化指标——库内现用 PESQ/STOI/DNSMOS 对辅音误抑制不敏感。
